## Извлечение
Массивы берутся по балансу квадратных скобок со снятием строк и
комментариев, затем `new Function('return (…)')` — литерал читает сам
движок. Регулярки бессмысленны: в описаниях скобки и кавычки.

## ГРАБЛИ MERMAID
1. `linkStyle N stroke:#RRGGBB;` — синтаксическая ошибка. Точка с запятой
   после цвета с решёткой не разбирается. У classDef и style работает
2. **Второй `linkStyle` для того же номера ЗАТИРАЕТ первый целиком.**
   Цвет отдельной строкой, толщина другой → 722 связи из 1613 (45%)
   теряли цвет типа и рисовались серыми. Писать одной строкой:
   `linkStyle 1,3,4 stroke:#3498DB,stroke-width:3.5px`
3. maxEdges (500) и maxTextSize (50000) — «защищённые»: директивой
   %%{init}%% не поднять, только вызовом mermaid.initialize
4. htmlLabels: mermaid 11 читает `htmlLabels ?? flowchart.htmlLabels ?? true` —
   нужен ключ ВЕРХНЕГО УРОВНЯ, вложенный перебивается настройкой приложения.
   При htmlLabels:true подписи уходят в foreignObject, а он НЕ РАСТРИРУЕТСЯ
5. Безусловный setAttribute('xmlns') на SVG от mermaid даёт повторное
   объявление → невалидный XML → строгий разбор в `<img>` падает

## DAGRE ПРОТИВ ELK
- dagre разваливается на кластерах: «Cannot set properties of undefined
  (setting 'order')» через ≈185 с. Порог — рёбра МЕЖДУ подграфами при
  полусотне подграфов: 357 ✓, 450 ✓, 502 ✗, 951 (полный) ✗
- ELK (@mermaid-js/layout-elk через registerLayoutLoaders) справляется:
  полный граф с подграфами 144,7 с, 57 кластеров, SVG 5,1 МБ
- ELK компактнее НЕ из-за прямых линий (их нет: ломаная с Q против
  цепочки кубических C), а из-за числа узлов на путь: 16,2 против 46,2.
  На мелких графах преимущества нет — координаты пишутся длинными дробями

## ЭКСПОРТ
- PNG: копия SVG с числовыми width/height, подложкой и снятым
  style="max-width" → Blob → `<img>` → канва → toBlob. Пределы канвы:
  сторона ~16 тыс., площадь ~1.2e8; множитель урезается сам
- НА КРУПНЫХ ГРАФАХ PNG БЕСПОЛЕЗЕН (×0.19 для полного) — только SVG
- Кнопка .mmd выгружает исходник БЕЗ поправки цветов под тему

## ТЕМА: ВТОРОЙ НАБОР ФАЙЛОВ НЕ НУЖЕН
Цвета данных (заливка по философу, линия по типу) от темы не зависят;
обвязка (подписи рёбер, рамки, наконечники, фон) задаётся темой mermaid.
Поправка adjustLinks симметрична: восемь цветов слабы на белом, два
(#34495E, #2C3E50) — на тёмном; двигаем до контраста 3,2:1, только stroke.

## ОГРАНИЧЕНИЯ file://
- Браузер ЗАПРЕЩАЕТ fetch соседнего файла («Failed to fetch»). Классические
  `<script src>` правилам источника не подчиняются и работают
- Внешний `<script src>` блокирует разбор документа: если CDN ЗАВИСАЕТ,
  разбор не продолжается никогда. Порядок — свой файл первым, CDN запасным
- ПРАВИЛО ПОСЛЕ ТРЁХ СБОЕВ У ПОЛЬЗОВАТЕЛЯ: отдельным файлом лежит ТОЛЬКО
  неизменённая опубликованная библиотека (sha256 сходится с npm), всё
  собранное мной уходит внутрь index.html. Дважды не грузился именно мой
  файл, опубликованный рядом грузился; воспроизвести не удалось ни разу

## УРОКИ О ПРОВЕРКАХ (пять ошибок в измерительном приборе)
1. Условие ожидания должно опознавать НОВОЕ состояние, а не любое
   непустое — «на канве есть svg» четырежды ловило чужой граф. Ждать
   появления имени нужного графа в строке состояния
2. Угловую точку PNG читать вырезкой 1:1, не ужимая картинку
3. Не заключать об отсутствии инструмента по неудаче одной установки:
   Chromium 141 лежит в /opt/pw-browsers, playwright и mermaid-cli — в
   /home/claude/.npm-global/lib/node_modules (нужен NODE_PATH)
4. Проверять не только отказ ресурса, но и ЗАВИСАНИЕ — разные состояния
5. Буквально исполненная просьба может быть хуже собственного суждения:
   сеть в критическом пути файла, чья цель — работать без сети, опасна

## ДОЛЯ ВЫПОЛНЕНИЯ (пользователь верно указал: кольцо со счётчиком времени — НЕ индикатор прогресса)
- Отчёты изнутри кадра: перехват Element.prototype.appendChild/insertBefore
  СИНХРОННЫЙ, поэтому работает при занятом потоке (таймеры внутри кадра
  молчат — за всю раскладку сработали дважды), postMessage кладёт отсчёт
  в очередь родителя, тот в другом процессе и жив
- ХОД РАБОТЫ (граф философов): вставки в DOM идут 0–9 % времени (0→7000),
  затем 9–96 % — НИ ОДНОГО СОБЫТИЯ (непрозрачный вызов раскладки), потом
  остаток. Доли этапов: легенда — раскладка 45 %; Хайдеггер 31 %;
  Кант с соседями подготовка 26 % / раскладка 65 %; философы 7 % / 89 %
- ТОЧНАЯ ВЕЛИЧИНА НАШЛАСЬ: вставок РОВНО 14 на элемент (узлы+рёбра),
  одинаково на всех графах → доля подготовки ИЗМЕРЯЕТСЯ
- Полоса из двух частей с честной подписью: подготовка — «измерено»
  (вставок / 14·(N+E)); раскладка — «оценка» по t ≈ 0,9·рёбер^1,6 мс
- Конец подготовки — по ОСТАНОВКЕ отчётов дольше 400 мс (раскладка DOM не
  трогает). Порог по счётчику не годится: доходило лишь до 89–99 %
- ПОДГОНКА ПОД СКОРОСТЬ МАШИНЫ ПО ВРЕМЕНИ ПОДГОТОВКИ ОТВЕРГНУТА ЗАМЕРОМ:
  на малых графах завышала оценку вдвое (полоса до 46 %). Голая модель
  точнее: на 444 рёбрах предсказала 15,5 с при действительных 17.
  Оставлена поправка в пределах ±25 %
- Ход полосы на философах: 18 % при 20 % времени, 50 % при 56 %, 82 % при
  92 %, к готовности 89 %. У Канта оценка завышена, доходит до 66 %
- ДЛЯ МОНОТОННОСТИ: в числителе оценочной части ИЗМЕРЕННОЕ время
  подготовки, а не предсказанное (иначе на переходе полоса пятилась с
  24 % на 18 %), плюс сторож «доля не уменьшается»
- НАЙДЕНА ПОБОЧНАЯ ОШИБКА: наложение отрисовок. Смена набора рисует свой
  первый граф; если тут же выбрать другой, поздний отчёт гасил ранний
  (полоса стояла на нуле), а завершившаяся старая отрисовка перезаписывала
  холст более новой. Введён номер задания renderSeq

## ПЕЧАТЬ ПОЛНОГО ГРАФА (просьба: SVG всех концепций с подграфами → PDF под бумагу)
- ШТАТНУЮ РАСКЛАДКУ ПЕЧАТАТЬ НЕЛЬЗЯ: elk.layered даёт 82728×41710 px при кегле
  13 px. Для подписи 7 pt нужен лист 15,7×7,9 м = 140 листов A0 или 1160 A3.
  Причина — заполнение: узлы 0,09 % холста, рамки философов 2,85 %, пусто 97 %
- РЕШЕНИЕ — ДРУГОЙ ДВИЖОК: elk.stress 8685×6004 (узлы 6,17 %, рамки 55,25 %),
  за 9 с — в 90 РАЗ меньше по площади и в 12 раз быстрее layered. elk.force
  то же самое, elk.mrtree 9964×5590. Перекрытий рамок 0, налезаний узлов 0
- ГРАБЛЯ ЗАМЕРА: getBBox отдаёт МЕСТНЫЕ координаты — все узлы оказывались в
  начале координат и «налезали» все на всех (102378 пар из 102378). Нужен
  getBoundingClientRect
- Отношение сторон 8685:6004 = 1,447, у листов A-ряда 1,414 — почти совпадение
- ВЫДАНО ДВА ФОРМАТА: concepts-full-A0.pdf (один лист 1189×841 мм, масштаб
  0,134 мм/px, кегль 4,9 pt, 0,8 МБ, текст векторный — извлекается 25890 знаков)
  и concepts-full-A3-atlas.pdf (26 страниц: обзор с сеткой разрезки + 5×5 плиток
  при кегле 8 pt; склейка 1,89×1,30 м, шаг 392×263 мм, перекрытие 8 мм, метки
  реза, врезка с положением плитки; 2,5 МБ; при 300 dpi подпись 33 точки)
- Печать в СВЕТЛОЙ теме, цвета связей поправлены под белый фон тем же правилом
- Сборка: render-print.mjs (elk.stress + светлая тема) → make-pdf.mjs poster|atlas,
  плитки сшиваются pypdf. Проверка страниц — растром (pypdfium2), а не
  извлечённым текстом: extract_text не учитывает обрезку overflow:hidden

- РАСТР ПЛОТНОЙ РАСКЛАДКИ (пользователь: «8685×6004 можно и в png»): да, укладывается.
  Предел канвы найден ПЕРЕБОРОМ: ×1 → 8685×6004 (52 Мпикс, 3,4 МБ, 2 с);
  ×1,5 → 13028×9006 (117 Мпикс, 6,2 МБ); ×1,886 → 16380×11324 (185 Мпикс, 8,5 МБ) —
  предел; ×2,5 → 21713×15010 (326 Мпикс) канва НЕ отдаёт PNG (сторона > 16384).
  Прежняя оценка площади 1.2e8 в просмотрщике занижена — на деле около 268 Мпикс
- Соответствие бумаге: ×1 = 189 dpi на A0 и 117 dpi на склейке атласа;
  ×1,886 = 357 и 221 dpi. Кегль в точках: 13 px при ×1, 24,5 px при ×1,886
- Для печати всё равно лучше PDF (подписи векторные); PNG — когда нужна картинка
- Сборка растров: make-png.mjs (перебор пределов), save-png.mjs (сохранение через
  download, чтобы не гонять мегабайты base64)

## ЧТО ФОРМАТ ТЕРЯЕТ
Описания связей; рубрики (subgraph древовиден, а рубрик у концепции
несколько — структурно кодируется только философ); temporal и ground

цели); годы, метрики, фильтры. Обратный перевод невозможен.
