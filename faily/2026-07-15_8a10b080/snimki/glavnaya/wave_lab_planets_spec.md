# wave_lab.html — спецификация: уровень моря, планеты, импакт-режим

Статус: черновик для утверждения перед реализацией.
Объём: три связанные фичи поверх уже существующего сферического кода. Без нового физического решателя.

---

## 1. Цель и границы

### 1.1. Что вводим
1. **Регулируемый уровень моря (flooding)** — глобальный ползунок, двигающий береговую линию по реальной топографии. Ядро всего изменения.
2. **Другие планеты** — Марс, Луна, Венера, Меркурий как выбираемые тела (цветная текстура + карта высот), поверх того же конвейера, что и Земля.
3. **Импакт-режим** — клик по сфере вбрасывает гауссов всплеск (метеорит/цунами).

### 1.2. Что НЕ вводим (явные non-goals)
- **Атмосферный решатель Эйлера / «погода на терраформированной планете».** Это отдельный solver несжимаемой жидкости, ортогональный идентичности `wave_lab` как FDTD-стенда. «Облегчённую погоду» при желании получаем как пресет начальных условий для уже имеющейся мелкой воды с Кориолисом — отдельной фичей это не оформляем.
- **Приливы (движущееся лунное форсирование).** Новая физика (объёмная сила в мелкой воде). Вынесено в §7 как возможное будущее, вне текущего объёма.
- **16-битная точность высот** на первом этапе (см. §3.2, решение по кодировке).

### 1.3. Принцип
Максимально переиспользуем существующий сферический код. Ни одна фича не добавляет нового решателя — только новый **слой данных** (знаковая высота вместо глубины), новую **скалярную величину состояния** (уровень моря) и **UI**.

## 2. Текущая архитектура (точки, которые трогаем)

Резюме по коду `wave_lab.html` (номера строк — ориентировочные, на момент написания):

| Элемент | Где | Роль |
|---|---|---|
| `physMap` (Uint8Array N) | объявл. ~567, заполн. в `samplePhys()` ~592 | `0 = суша`, `1..255 = глубина океана`; красный канал `earth_phys.png` |
| `sphereBuild()` | ~602 | волна на сфере (`model==='sphere'`): `physMap→ wall/C2/elem` |
| `swBuildEarth()` | ~665 | мелкая вода на сфере (`model==='swater' && swSphere`): `physMap → depth/wall` |
| `planet` | ~566 | `'earth' \| 'uniform'` |
| `SPHERE_C2` | ~564 | опорный курант² на сфере |
| `loadPlanet(cb)` | ~583 | грузит `imgColor` (цвет) + `imgPhys` (глубина) |
| `planetUpload()` | ~2041 | заливает `imgColor` в `planetTex` (WebGL) |
| шейдеры сферы | 3D ~1915, 2D ~3326, rde-3D ~2998 | `base = texture(uPlanet)`, волна через LUT, суша = ветка по флагу |
| `glFlagsDirty` / флаг-текстура | по коду | признак «суша/стена» на GPU; уже есть механизм пересборки |
| Кориолис | ~974 `fcor=swOmega*cos(th)` | мелкая вода на сфере |

**Критический факт:** обе сборки (`sphereBuild`, `swBuildEarth`) определяют сушу как `physMap[k]===0`. Береговая линия «зашита» в данные. Пока карта несёт только глубину океана (суша занулена), поднять/опустить уровень моря нельзя — нет высот суши. Это блокер §4 и первопричина замены слоя данных.

## 3. Слой данных: от «глубины» к «знаковой высоте»

### 3.1. Новое поле `elevMap`
Заменяем семантику входной карты: вместо «глубина океана, суша=0» — **знаковая высота рельефа** (и суша, и дно как единое поле).

- Новый ассет на планету: `{planet}_elev.png` — 8-битный серый PNG равного разрешения (1024×512), где значение `g∈[0,255]` линейно кодирует высоту:
  `elev(g) = ELEV_MIN + (g/255) · (ELEV_MAX − ELEV_MIN)` (в метрах либо в нормированных единицах, см. §3.3).
- Уровень моря по умолчанию соответствует некоторому `g_sea` (для Земли — известное значение, откалиброванное при подготовке данных).
- Новый рантайм-буфер: `elevMap = Float32Array(N)` — высота в рабочих единицах на ячейку. Заполняется новой функцией `sampleElev()` (аналог `samplePhys`, но масштабирует красный канал в `elev` через `ELEV_MIN/ELEV_MAX` планеты).

`physMap` (Uint8 глубины) — **удаляется** как источник; при необходимости обратной совместимости глубина выводится из `elevMap` и `seaLevel` на лету (см. §4.2).

### 3.2. Решение по кодировке (нужно подтвердить)
- **Вариант A (рекомендуемый на старт):** 8 бит. Шаг по высоте ≈ `(ELEV_MAX−ELEV_MIN)/255`. Для Земли (−10000…+9000 м) это ≈ 75 м/уровень — визуально приемлемо, конвейер совпадает с текущим `samplePhys` (чтение одного канала). Минимум кода и риска.
- **Вариант B (апгрейд позже):** 16 бит (`PNG I;16`) или упаковка высоты в два канала (R=старший, G=младший). Даёт ~0.3 м/уровень. Требует правки чтения (не `d[k*4]`, а сборка из двух каналов). Оставляем как будущий апгрейд, точечно затрагивающий только `sampleElev()`.

Решение по умолчанию: **A**. B — если после теста ступеньки по высоте будут заметны на пологом рельефе при затоплении.

### 3.3. Единицы
Рабочие единицы `elev` — нормированные `[-1, +1]` (0 = опорный уровень моря планеты), чтобы физика (`C2`, `depth`) не зависела от абсолютных метров. Метры хранятся только в метаданных планеты (`ELEV_MIN_M`, `ELEV_MAX_M`) для подписи ползунка в HUD. `seaLevel` живёт в тех же нормированных единицах.

### 3.4. Подготовка ассетов (offline, разовая)
Скрипт подготовки (мой, не в рантайме) собирает на каждую планету пару `{planet}_color.jpg` + `{planet}_elev.png` из репозитория Берглунда:

- **Земля:** высота суши из `digital_elevation_model_large.ppm` + глубина океана из `bathymetry_gebco_2560_1280_mod2_color.ppm`, сшитые в одну знаковую карту; `g_sea` фиксируется на границе. Цвет — `Earth_Map_Blue_Marble_2002_large.ppm` (уже есть как `earth_color.jpg`).
- **Марс:** DEM `marscyl2.ppm`, цвет `Mars_Viking_ClrMosaic…ppm`.
- **Луна:** DEM `Moon_LRO_LOLA_global_LDEM_1024.ppm`, цвет `Moon_photo_map.ppm`.
- **Венера:** DEM `Venus_Magellan_Topography…ppm` (с обработкой NODATA-дыр, как в `init_dem`), цвет `Venus_map_NASA_JPL…ppm`.
- **Меркурий:** DEM `Mercury_Messenger_DEM_Global…ppm`, цвет `Mercury_color_photo.ppm`.

Все PPM репозитория — **текстовые (ASCII)**, читаются как один integer на канал (учтено в моём загрузчике). Каждая карта нормируется в `[-1,+1]` по своим `ELEV_MIN/MAX`; per-planet метаданные фиксируются в таблице §5.1.

Важно: **все карты приводятся к общей equirectangular-рамке 1024×512, roll=0**, чтобы цвет и высота совпадали пиксель-в-пиксель (как уже сделано для Земли).

## 4. Фича 1 — уровень моря (flooding)

### 4.1. Состояние
```
let seaLevel = 0.0;          // нормированный уровень, [-1..+1]; per-planet дефолт
```
Диапазон ползунка: `[ELEV_MIN_norm, ELEV_MAX_norm]` = `[-1, +1]`. Дефолт для Земли = 0 (текущая береговая линия). Для «сухих» планет дефолт ниже минимума рельефа (нет воды).

### 4.2. Классификация среды (переписываем обе сборки)
Общий помощник, чтобы `sphereBuild` и `swBuildEarth` не разъезжались:
```
// возвращает {isWater, depthNorm} для ячейки k при текущем seaLevel
function cellHydro(k){
  const e = elevMap[k];
  if(e < seaLevel){ return { isWater:true,  depth: seaLevel - e }; }  // вода
  return { isWater:false, depth: 0 };                                  // суша
}
```

`sphereBuild` (волна):
```
const {isWater, depth} = cellHydro(k);
if(!isWater){ wall[k]=1; C2[k]=SPHERE_C2; }
else { const h = clamp01(depth); C2[k] = SPHERE_C2 * Math.max(0.06, h); elem[k] = (h<0.35)?1:0; }
```

`swBuildEarth` (мелкая вода): аналогично, `depth[k] = Math.max(0.05, depthNorm)` для воды, `wall[k]=1; depth[k]=0.02` для суши.

Итог: `physMap==0`-логика заменена на `elev < seaLevel`. Береговая линия теперь **производная** от `seaLevel`, а не вшита.

### 4.3. Пересборка при движении ползунка
```
function setSeaLevel(v){
  seaLevel = v;
  if(model==='sphere') sphereBuild();
  else if(model==='swater' && swSphere){ swBuildEarth(); }
  updateHud();                       // подпись: «уровень моря: +NNN м»
}
```
- Пересборка — та же, что при смене профиля/планеты; частоту дебаунсим (throttle на `input`, полная сборка на `change`), т.к. полный проход по `N` ячейкам может быть заметен на больших сетках.
- Поле волны при пересборке сбрасывается (`cur/prv.fill(0)` уже внутри сборок) — это ожидаемо: сменили геометрию бассейна.

### 4.4. Рендеринг затопленных ячеек
- Флаг «суша/вода» на GPU обновляется через уже существующий `glFlagsDirty` → `gpuUpload()`.
- Опционально: подсвечивать «залитую сушу» (ячейки, где `elev>0`, но `elev<seaLevel`) отдельным оттенком — аналог `HUE_FLOODED` у Берглунда. Реализация: третий флаг в `elem`/флаг-текстуре + ветка в шейдере (`mix(base, floodTint, k)`); низкий приоритет, за флагом настройки.

### 4.5. UI
- Ползунок «Уровень моря» рядом с блоком сферы. Активен только когда `model==='sphere'` или (`swater`+`swSphere`).
- Подпись значения в метрах (через per-planet `ELEV_*_M`).
- Кнопки-пресеты: «−100 м», «текущий», «+100 м», «+максимум» (быстрая демонстрация «затопить/осушить»).

## 5. Фича 2 — другие планеты

### 5.1. Метаданные планет
Единая таблица (единственный источник правды):
```
const PLANETS = {
  earth:   { color:'earth_color.jpg',   elev:'earth_elev.png',   elevMinM:-10000, elevMaxM:9000,  seaDefault:0.0,  hasBathy:true },
  mars:    { color:'mars_color.jpg',    elev:'mars_elev.png',    elevMinM:-8000,  elevMaxM:21000, seaDefault:-1.0, hasBathy:false },
  moon:    { color:'moon_color.jpg',    elev:'moon_elev.png',    elevMinM:-9000,  elevMaxM:10000, seaDefault:-1.0, hasBathy:false },
  venus:   { color:'venus_color.jpg',   elev:'venus_elev.png',   elevMinM:-3000,  elevMaxM:11000, seaDefault:-1.0, hasBathy:false },
  mercury: { color:'mercury_color.jpg', elev:'mercury_elev.png', elevMinM:-6000,  elevMaxM:5000,  seaDefault:-1.0, hasBathy:false }
};
let currentPlanet = 'earth';
```
(значения `elevMinM/MaxM` уточняются при подготовке данных §3.4; здесь — плейсхолдеры).

### 5.2. Загрузка
`loadPlanet(cb)` обобщается: берёт `PLANETS[currentPlanet].color/elev`, грузит обе картинки, вызывает `sampleElev()`; при готовности `planetUpload()` (цвет→текстура) и сборку текущего режима.
- Добавить `onerror` на обе картинки (сейчас при неудаче загрузки `planetReady` молча не выставляется). Логировать понятное сообщение (файл не найден / открыто через `file://`).

### 5.3. Смена планеты
```
function setPlanet(name){
  currentPlanet = name; planetReady=false; elevMap=null;
  seaLevel = PLANETS[name].seaDefault;
  loadPlanet(()=>{ planetUpload(); (model==='sphere'?sphereBuild:swBuildEarth)(); rdeSeed?.(); updateHud(); });
}
```
- Диапазон/подписи ползунка уровня моря обновляются под выбранную планету.
- Для планет без океанов (`hasBathy:false`) осмысленны сценарии: сухая (волны только через импакт по твёрдой поверхности — фактически отражения) или «затопить» ползунком (аналог роликов «Flooding Mars/Moon/Venus/Mercury»).

### 5.4. UI
Селектор планеты (5 кнопок или dropdown) в блоке сферы. При выборе — `setPlanet(name)`.

## 6. Фича 3 — импакт-режим

### 6.1. Поведение
Режим-тумблер «Импакт». Когда включён, клик по сфере вбрасывает локальный гауссов всплеск в поле:
- волна (`sphere`): в `cur` (и согласованно в `prv`, чтобы задать начальную скорость ≈0 или направленный фронт).
- мелкая вода (`swater`): в высоту `depth`/поле уровня.

```
function impactAt(i, j, amp, radius){
  for(dj..) for(di..){
    const k=wrapIndex(i+di, j+dj);
    const r2=(di*di+dj*dj)/(radius*radius);
    if(r2<=9) cur[k] += amp*Math.exp(-r2);   // ± согласовать со знаком поля
  }
  // учесть заворот по долготе (i) и зажатие по широте (j)
  glFieldDirty=true; if(gpuReady) gpuUploadField();
}
```

### 6.2. Экран → ячейка
- **2D-сфера** (`sphere2D`/2D-swater): экранные UV прямо соответствуют `(i,j)` — тривиально.
- **3D-сфера:** нужен пикинг. Рейкаст из камеры на единичную сферу (пересечение луч-сфера уже вычислимо из матриц вида/проекции, доступных в рендере), затем точка сферы → (φ,θ) → `(i,j)`. Реализация: обратное преобразование того же отображения, что в вершинном шейдере сферы. Изолировать в `screenToSphereIJ(px,py)`.
- Если пикинг в 3D окажется трудоёмким — на первом этапе допускается импакт только в 2D-проекции, 3D — следующим шагом.

### 6.3. UI
- Тумблер «Импакт-режим» + слайдеры «амплитуда» и «радиус».
- Подсказка курсора при наведении на сферу.

## 9. Обратная совместимость и риски
- **Регрессия `physMap`:** любые прочие обращения к `physMap` (проверить полнотекстово) переводятся на `elevMap`/`cellHydro`. Иначе — рассинхрон береговой линии между режимами.
- **Единый источник классификации:** суша/вода определяется ТОЛЬКО через `cellHydro()`. Не дублировать порог в шейдере и в CPU-сборке — только флаг-текстура из CPU.
- **Производительность:** пересборка на каждый tick ползунка — по `N`. Дебаунс + (опц.) инкрементальное обновление только флаг-текстуры без полной перезаливки поля.
- **Устойчивость:** `SPHERE_C2` и `swInvSinMax()` рассчитаны на текущие диапазоны глубин; при экстремальном затоплении (очень глубоко) проверить Курант — при необходимости клампить `depth` сверху.
- **file://:** внешние карты требуют http-сервера (как уже отмечено при выносе картинок). `onerror` даёт явную диагностику.

## 10. Этапы реализации (предлагаемый порядок)
1. **Данные:** собрать знаковый `earth_elev.png` из репозиторного DEM+GEBCO, откалибровать `g_sea` и `ELEV_*`.

4. **Остальные планеты** (Луна, Венера, Меркурий) — только подготовка данных + строки в `PLANETS`.
5. **Импакт-режим:** сперва 2D-пикинг, затем 3D-рейкаст.
6. Полировка HUD/UI, опц. подсветка затопления.
