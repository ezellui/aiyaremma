# Использование констант в файлах Фазы 1

## 1. Использование `errorCodes.js` (Коды ошибок)

### Библиотеки обработки ошибок:
- `shared/lib/errors/AppError.js` - использует коды ошибок в конструкторе
- `shared/lib/errors/HttpErrors.js` - использует HTTP коды ошибок
- `shared/lib/errors/ValidationError.js` - использует коды ошибок валидации
- `shared/lib/errors/NotFoundError.js` - использует код ошибки NOT_FOUND

### HTTP-утилиты:
- `shared/lib/http/responseFormatter.js` - использует коды ошибок при форматировании ответов

### Логирование:
- `shared/lib/logging/logger.js` - может использовать коды ошибок для категоризации логов
- `shared/lib/logging/requestLogger.js` - логирует коды ошибок в запросах

### Шаблоны контроллеров и сервисов:
- `templates/backend/controllers/crud-controller-template.js` - использует коды ошибок в обработчиках
- `templates/backend/controllers/specialized-controller-template.js` - использует коды ошибок
- `templates/backend/services/crud-service-template.js` - использует при генерации ошибок
- `templates/backend/services/specialized-service-template.js` - использует при генерации ошибок

### Шаблоны тестов:
- `templates/backend/tests/unit-test-template.js` - проверяет коды ошибок
- `templates/backend/tests/integration-test-template.js` - проверяет коды ошибок
- `templates/api-tests/api-test-template.js` - проверяет коды ошибок в API

## 2. Использование `statuses.js` (Статусы)

### Модели:
- `shared/models/User.js` - статус пользователя (active, inactive, blocked)
- `shared/models/Concept.js` - статус концепции (draft, published, archived)
- `shared/models/Thesis.js` - статус тезиса (draft, reviewed, approved)

### Валидация:
- `shared/lib/validation/validators.js` - валидация статусов
- `shared/lib/validation/schemas/conceptSchemas.js` - проверка допустимых статусов концепций
- `shared/lib/validation/schemas/thesisSchemas.js` - проверка допустимых статусов тезисов

### Шаблоны:
- `templates/backend/services/crud-service-template.js` - работа со статусами сущностей
- `templates/backend/services/specialized-service-template.js` - работа со статусами

### Миграции БД:
- `db/postgres/migrations/00002_create_concepts_table.sql` - поле status с дефолтным значением
- `db/postgres/migrations/00007_create_user_activity_table.sql` - статусы активности

### MongoDB схемы:
- `db/mongodb/schemas/theses.js` - валидация статусов тезисов
- `db/mongodb/schemas/generatedElements.js` - статусы сгенерированных элементов

## 3. Использование `roles.js` (Роли)

### Аутентификация и авторизация:
- `shared/lib/auth/jwtHelper.js` - включение роли в JWT токен
- `shared/lib/auth/roleHelper.js` - проверка ролей и прав доступа

### Модели:
- `shared/models/User.js` - роль пользователя

### Валидация:
- `shared/lib/validation/validators.js` - валидация ролей
- `shared/lib/validation/schemas/userSchemas.js` - проверка допустимых ролей (если будет создан)

### Шаблоны:
- `templates/backend/controllers/crud-controller-template.js` - проверка прав доступа по ролям
- `templates/backend/controllers/specialized-controller-template.js` - проверка прав доступа

### Миграции и сидеры:
- `db/postgres/migrations/00001_create_users_table.sql` - поле role
- `db/postgres/seeds/00003_test_users.sql` - тестовые пользователи с различными ролями

## 4. Использование `philosophyConstants.js` (Константы для философских понятий)

### Модели:
- `shared/models/Concept.js` - типы концепций, уровни инновационности
- `shared/models/Graph.js` - типы узлов и связей графа
- `shared/models/Thesis.js` - типы тезисов, стили

### Валидация:
- `shared/lib/validation/validators.js` - валидация философских констант
- `shared/lib/validation/schemas/conceptSchemas.js` - допустимые типы концепций
- `shared/lib/validation/schemas/graphSchemas.js` - типы связей, направления
- `shared/lib/validation/schemas/thesisSchemas.js` - типы тезисов

### Утилиты форматирования:
- `shared/lib/formatting/stringFormatters.js` - форматирование философских терминов

### Миграции БД:
- `db/postgres/migrations/00002_create_concepts_table.sql` - типы концепций
- `db/postgres/migrations/00017_create_category_templates_table.sql` - типы категорий
- `db/postgres/migrations/00018_create_relationship_type_templates_table.sql` - типы связей
- `db/neo4j/migrations/00004_category_nodes.cypher` - свойства категорий
- `db/neo4j/migrations/00005_relationship_types.cypher` - типы связей

### Сидеры:
- `db/postgres/seeds/00001_philosophers.sql` - философские традиции
- `db/postgres/seeds/00002_traditions.sql` - философские традиции
- `db/postgres/seeds/00004_test_concepts.sql` - типы концепций
- `db/postgres/seeds/00005_system_categories.sql` - системные категории
- `db/postgres/seeds/00006_system_relationship_types.sql` - системные типы связей
- `db/neo4j/seeds/00001_test_graphs.cypher` - типы узлов и связей
- `db/mongodb/seeds/00001_test_theses.js` - типы и стили тезисов

### MongoDB схемы:
- `db/mongodb/schemas/theses.js` - типы тезисов, стили
- `db/mongodb/schemas/categoryDescriptions.js` - типы категорий
- `db/mongodb/schemas/relationshipDescriptions.js` - типы связей
- `db/mongodb/schemas/conceptAnalyses.js` - типы анализов
- `db/mongodb/schemas/historicalContexts.js` - философские периоды
- `db/mongodb/schemas/practicalApplications.js` - области применения

### Клиенты сервисов:
- `templates/backend/clients/service-client-template.js` - может использовать константы в запросах
