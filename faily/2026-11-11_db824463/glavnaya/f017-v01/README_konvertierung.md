# Wittgenstein's Nachlass (BEE 2000) → XML → HTML: что сделано

Итог работы по `Nachlass.iso`: обе транскрипции, нормализованная (NORM) и дипломатическая (DIPLO), сконвертированы целиком. Все 156 единиц хранения (Ms 101–183, Ts 201–245, диктовки 301–310) есть в обеих версиях. Получилось по одному XML-файлу на единицу и версию, итого 312 документов. Из них собран статический сайт: отдельная страница на каждую единицу, 14 страниц-серий (например, «Тома I–XVIII», «Голубая и Коричневая книги», «Исследования»), оглавление.

**Правовая оговорка.** Экспорт для пользователя Guest в программе заблокирован. Эту защиту я не снимал: текст получен только разрешённой изданием печатью. Результат годится для личной работы. Распространять его (выкладывать сайт, передавать файлы) можно только с согласия правообладателей: Oxford University Press, The Wittgenstein Trustees и University of Bergen. Поэтому сайт отдаётся архивом, а не публикуется ссылкой.

## Что лежит в архивах

- **`bee_site.zip`** — сайт. Открывать `index.html` в браузере, сервер не нужен.
  - Страница единицы: `items/<n>.norm.html` или `items/<n>.diplo.html`, с перекрёстной ссылкой на вторую версию.
  - Страница серии: `series/<id>.<версия>.html`.
  - Переключатели в шапке страницы: «Alternativen» показывает нерешённые варианты, «Personenregister» — указатель лиц.
- **`bee_xml.zip`** — 312 XML-файлов вида `<n>.norm.xml` и `<n>.diplo.xml` плюс `img/` (1 855 рисунков). Это основной результат: HTML собирается из него заново одной командой.
- **`bee_scripts.zip`** — весь конвейер (Python и bash), описан ниже.

## Модель данных (XML, близкий к TEI)

```
<item n="105" title="Band I …" version="norm|diplo">
  <pb n="43" facs="105/047.jpg"/>                      страница рукописи + имя файла факсимиле
  <rec page="43" date="6 Feb, 1929">                   запись BEE (заметка) — только в NORM
    <p rend="right|center">…</p>
  </rec>
  <notes><note n="1">Vgl. Faksimile; leere Seite.</note></notes>   всплывающие примечания (DIPLO)
</item>
```

Строчные элементы:

| Элемент | Что означает |
|---|---|
| `<ed>` | редакторская вставка (в издании красная) |
| `<app><rdg/>…<lem/></app>` | нерешённые варианты: последний — `lem` |
| `<person key="Russell, Bertrand"/>` | указатель лиц |
| `<formula notation="…">` | нотация: логика, математика; `<hi rend="sub/sup">` внутри |
| `<figure src="img/…png" desc="Vierecke; Quadrat"/>` | рисунок |
| `<figure desc="…" missing="1"/>` | рисунок, который не удалось перенести; показан как подпись в рамке |
| `<del>`, `<hi rend="u/b/i/alt">` | зачёркнутое; подчёркивание, жирный, курсив, вариант |

Только в DIPLO:

| Элемент | Что означает |
|---|---|
| `<lb/>` | конец строки рукописи |
| `<subst><del/><add/></subst>` | `[a\|b]`: замена a на b |
| `<add place="interlinear\|inline">` | `«…»` и `‹…›`: вставки |
| `<hi rend="code">` | шифр Витгенштейна (в издании серая подложка) |
| `<date when=…/>` | дата как веха в тексте |
| `<notation key=…/>` | дескриптор рисунка или нотации |

## Конвейер

### 1. Печать

Folio VIEWS 3.1 запускается под Wine (Xvfb) и печатает в CUPS-PDF. Управление с клавиатуры (xdotool) — `batch_segments2.sh`, `print_sel.sh`, `resume.sh`.

- В Page Setup включён Hidden Text. Благодаря этому печатаются маркеры записей, даты, страницы с именами файлов факсимиле, указатель лиц и дескрипторы нотации и рисунков.
- **Проход A** печатает текст без обработчика растровых изображений. С растрами Folio падает: накапливается утечка в FOLIOBMP.
- Печать идёт сегментами. После сбоя или перезапуска среды она продолжается с последнего заголовка единицы. Две копии Wine-префикса печатали NORM и DIPLO параллельно.
- В DIPLO рукопись Ms 101 первоначально обрывалась на 29r. Её перепечатал `batch_one.sh` в режиме одной единицы; теперь она полная.

### 2. PDF → XML (`bee_pdf2xml.py`, сборка по единицам `bee_build.py`)

Символы восстанавливаются по номерам глифов, а не по ToUnicode — он в этих PDF испорчен.

- **TrueType:** AGL плюс собственная карта для шрифтов WAB (`wab_map.json`, 333 глифа).
- **Symbol:** собственный `symbol.ttf` с cmap (3,0).
- **Растровые Type 3** (машинопись, Courier, нотация):
  - коды ASCII и cp1252 берутся как есть;
  - перенумерованные глифы — по md5 их процедуры отрисовки;
  - общая таблица выучена по всем распечаткам (`t3_learn.py`, файл `t3_auto.json`, 386 глифов);
  - ещё 85 глифов определены вручную по контактным листам (`glyphs3.json`).
- **Итог: 0 неопознанных символов в обеих версиях, во всех 156 единицах.**
- Стили определяются по цвету (синий текст, красная редактура, тёмный цвет последнего варианта) и шрифту.
- Подчёркивание и зачёркивание — по тонким прямоугольникам.
- Индексы распознаются по смещению от базовой линии.
- Абзацы — по отступу, интервалу и выключке.
- В DIPLO строки рукописи сохраняются (`<lb/>`). Серые подложки размечаются как шифр. Блок «Endnotes» становится примечаниями.

### 3. Рисунки

Растры не удалось получить печатью:

- **Через CUPS** палитра индексированных растров приходит пустой — все пиксели чёрные.
- **«Печать в файл»** даёт PostScript, где индексы целы и пустую палитру можно заменить серой шкалой (`print_ps.sh`, `ps_fix.py`). Но на части записей Folio под Wine падает уже при вёрстке страницы, причём воспроизводимо.

Поэтому рисунки сняты с экрана, где Folio рисует их правильно, в исходных цветах:

1. Запрос `[Field Graphics] | [Field Tables] | [Field Music]` в режиме «Records With Hits» оставляет в окне только 1 526 записей с рисунками.
2. Цвет фона окна в реестре Wine сменён на светло-жёлтый. Растр — непрозрачный прямоугольник — после этого отделяется от фона точно по своим границам.
3. `fig_capture.py` и `fig_chunks.sh` пролистывают окно порциями по 50 записей и склеивают экраны по сдвигу. Рисунок — это прямоугольник справа от подсвеченного дескриптора. Снято 2 902 растра.
4. `bee_figs2.py` сопоставляет снятые растры с местами рисунков в тексте. Опора — длина дескриптора: моноширинный шрифт на экране даёт 8 px на знак плюс 16 px. Работает динамическое программирование в полосе.
   - Из 1 939 мест рисунков в тексте сопоставлено 1 845.
   - Использовано 2 640 растров: одно место может соответствовать нескольким растрам.
5. `bee_figs_diplo.py` переносит те же растры в DIPLO по дескриптору и странице факсимиле (допускается соседняя страница). Вставлено 2 039 растров.

### 4. HTML

`bee_xml2html.py` рендерит страницы, `bee_site.py` собирает сайт. Список серий — в `series.json`: это черновик, его легко править.

## Ограничения и что можно доделать

- **Нотация, нарисованная растром** (двумерные формулы и т. п.), не входит в поле Graphics. Такие места остаются подписью в рамке. Их можно снять тем же способом, запросом по полям Mathematics и Logic, но это ещё около 5 000 записей.
- **Сопоставление рисунков статистическое.** Часть растров могла попасть к соседнему месту. Около 100 мест из поля Graphics остались подписью.
- **В NORM строки с маленьким встроенным рисунком часто выделены в отдельный абзац.** Это косметика.
- **Даты «1 Jan, 1932» у машинописей** — так их хранит само издание: известен только год.
- **Сопоставление NORM↔DIPLO по записям не сделано:** в дипломатической распечатке нет маркеров записей. Выравнивание возможно по страницам факсимиле (`pb/@facs` совпадают) — как в `transfer.py` проекта HWPh.
- **ITEM.NFO** (метаданные единиц: датировки, описание) не печатался. Это следующий кандидат.
