# Nachlass.iso — анализ и путь к HTML

*Wittgenstein's Nachlass: The Bergen Electronic Edition (OUP / University of Bergen, 2000), текстовый диск, тома I–IV.*

## 1. Короткий ответ

Преобразовать можно, и с хорошим качеством. Тексты не «замурованы» намертво, но и прямого пути нет:

* Тексты лежат в базах **Folio VIEWS 3.1** (`*.NFO`). Это закрытый бинарный формат со сжатием и обфускацией. Открытого описания нет, а готовые конвертеры (например, `imazen/folioxml`) требуют, чтобы базу сначала выгрузили в Folio Flat File. Разбирать формат с нуля нецелесообразно.
* Родной просмотрщик с диска (`BVIEWS.EXE`, «Folio **Bound** VIEWS 3.1a», 16-битный) **запускается под Wine** на Linux, и издание в нём полностью читается.
* Экспорт (RTF/ASCII/Word) в программе есть, но **издатель закрыл его правами**: у пользователя Guest снят флаг «Save As», и программа отвечает *«Insufficient security to perform operation»*. Копирование в буфер на практике тоже ничего не даёт. **Печать разрешена явно.**
* Печать в PDF (CUPS-PDF) даёт **текстовый, а не растровый** PDF. По встроенным шрифтам из него восстанавливается точный Unicode, а цвет, подчёркивания, курсив и маркеры страниц несут редакционную разметку. На пробном фрагменте MS 101 прототип конвертера уже даёт чистый HTML (файл `probe_ms101.html` приложен).

Итог: путь **«печать → PDF → разбор → HTML»** рабочий, законный и автоматизируемый. По одному HTML на единицу каталога (Item) делается естественно: издание и так устроено по единицам с постраничными якорями. Серии связанных текстов собираются поверх этого слоя.

Права Guest я снимать не стал, хотя диалог Security позволяет их редактировать. Это обход защитной меры издателя, и я не буду этого делать и помогать с этим. Для задачи это и не нужно.

## 2. Что на диске

| Файл | Размер | Содержимое |
|---|---|---|
| `INFOBASE/NORM.NFO` | 78 МБ | Нормализованная транскрипция, 54 539 записей |
| `INFOBASE/DIPLO.NFO` | 75 МБ | Дипломатическая транскрипция |
| `INFOBASE/ITEM.NFO` | 6,7 МБ | Item List: каталог единиц, страницы, ссылки на факсимиле |
| `INTRO.NFO`, `USER.NFO`, `README.NFO`, `START.NFO` | ≤ 3 МБ | Введение (с ключом к разметке), руководство, readme, стартовая база |
| `FULL.NFO` | 1 МБ | Справка самого Folio VIEWS |
| `BVIEWS.EXE` + DLL | | Folio Bound VIEWS 3.1a (Win 3.x, NE) и фильтры `TORTF`, `TOASCII`, `WWORDEXP`, `TOWP*` |
| `*.TTF` в корне | | Шрифты Plantin OUP, Arial OUP, WAB (`WABOUP`, `WABLAST`, `WABMATH`) |
| `INFOVIEW/` | | InfoView Lite — просмотрщик факсимиле |

**Факсимиле на этом диске нет.** Это текстовый диск, изображения лежат на отдельных Image Discs (во введении упоминаются диски 4a/4b, всего 21 444 изображения). В записях есть пути к ним вида `101\001.jpg`, так что HTML может ссылаться на факсимиле, если у вас есть эти диски.

### Как устроен текст внутри

* Иерархия: **Item** (по каталогу фон Вригта: MSS 101–183, TSS 201–245, диктовки 301–311) → **Page** (имена страниц `1r`, `34v`, `Front Cover`…) → текст. В оглавлении на верхнем уровне 156 записей.
* У каждой страницы есть кнопки‑ссылки **D / N / I / P**: на ту же страницу в дипломатической или нормализованной версии, в Item List и на факсимиле. Значит, все четыре слоя связаны постраничными ключами, и эту связь можно сохранить в HTML.
* Две версии текста:
  * **Normalized** — читаемый текст: зачёркнутое убрано, сокращения раскрыты, орфография нормализована, *Geheimschrift* расшифрована. При неразрешённых вариантах показан последний, остальные — скрытый текст (hidden).
  * **Diplomatic** — максимально близко к рукописи: зачёркивания, вставки, переставляемые фрагменты, шифр *ad literam* (на пробе MS 101 видно «Zfu wvo dvt…» — инверсный алфавит a↔z).
* Порядок текста не всегда физический. MS 105/106 транскрибированы по ходу текста (сначала recto, потом verso). MS 107 и 108 перемежаются. В MS 101–103 философские записи (recto) чередуются с шифрованным дневником (verso). Поэтому «один текст» ≠ «одна единица хранения», об этом в §5.

### Ключ к разметке (из INTRO.NFO), который переносится в HTML

| Normalized | Diplomatic |
|---|---|
| **красный** — редакционные пометы и правки (в т.ч. нормализованные буквы) | красный — редакционные пометы |
| подчёркнутое — прямое подчёркивание / разрядка | подчёркнутое — прямое подчёркивание |
| *курсив* — добавлено другой рукой | серый — волнистое/пунктирное подчёркивание |
| **полужирный** — ссылки по указаниям В. | зачёркнутое — вычеркнуто |
| **чёрный** — последний из неразрешённых вариантов (прочие скрыты) | `[a\|A]` надписано, `«…»` вставки, `<>` вставка в строке, стрелки перестановок и т.д. |

## 3. Что проверено на практике

| Проверка | Результат |
|---|---|
| Запуск `BVIEWS.EXE` под Wine 9 (Ubuntu, i386) | Работает. Нужна ручная «установка»: распаковать `*.??_` (SZDD) и прописать фильтры в `C:\WINDOWS\VIEWS.INI` |
| File → Save As (экспорт RTF/ASCII/DOC) | Диалог открывается, фильтры видны, но экспорт отклоняется: *Insufficient security*. У Guest разрешены только **Print** и сверка shadow-файла |
| Edit → Copy | Пункт активен, но буфер остаётся пустым |
| File → Print → CUPS-PDF | **Работает** для выделенного фрагмента любой длины (Print range: Selection). «All» печатает только текущую запись |
| Текст в PDF | Настоящий текстовый слой (TrueType-подмножества + Type 3), не растр |
| Кодировка | Wine/Ghostscript не пишут ToUnicode, поэтому «в лоб» получаются `û` вместо `ß`, `©` вместо `'`, `Ð` вместо `—`. **Решено точно:** подмножество хранит исходные номера глифов, по ним берутся имена глифов из оригинальных TTF с диска (`germandbls`, `emdash`…) и переводятся в Unicode |
| Логические/математические знаки | Под Wine по умолчанию теряются (подставляется WineSymbol без глифов). **Решено:** в Wine подкладывается шрифт с кодировкой Symbol, коды сохраняются и переводятся по таблице Adobe Symbol. Пример: `ϕ(x)  (x).ϕx  (∃x).ϕx` из MS 101 |
| Цвет, подчёркивание, курсив | Цвет сохраняется у каждого символа. Подчёркивание — тонкий прямоугольник цвета текста под базовой линией, распознаётся. Курсив — отдельный шрифт PlantinOUP-Italic |
| Маркеры страниц | Строки «Item 101 Page 34v» (Arial OUP Bold, красный) — надёжные якоря |
| Дипломатическая версия | Печатается. Зачёркивания и подчёркивания — векторные линии (восстанавливаются геометрией), шифр и спецзнаки на месте |
| Битмапы (формулы, рисунки) | Издание вставляет их картинками. В PDF они встроены и извлекаются (`pdfimages`), качество по всему корпусу ещё не оценено |

## 4. Варианты действий

### А. «Печать → PDF → HTML» с диска *(рекомендую как основной)*

1. **Среда.** Linux + Wine (i386) + CUPS-PDF + Xvfb + xdotool. Всё это у меня уже собрано и проверено. Альтернатива — 32-битная Windows (XP/7 x86) в виртуалке: там есть родной `Symbol.ttf`, но печать в PDF придётся настраивать отдельно. На 64-битной Windows 7 программа не запустится: 16-битные приложения там не поддерживаются.
2. **Пакетная печать по единицам.** Для каждого Item в NORM и в DIPLO: перейти к заголовку единицы, выделить до заголовка следующей, напечатать Selection в `ms101.norm.pdf` и т.п. Управление через xdotool. Перед печатью включить в Page Setup / View показ **скрытого текста** — это настройка просмотра, а не права, — чтобы получить и неразрешённые варианты. Это ещё нужно проверить.
3. **PDF → промежуточный формат (JSON).** Блоки и строки, спаны с классами (`txt` / `ed` / `alt` / `u` / `i` / `sup`), якоря страниц, картинки. Ядро уже написано (`folio_pdf2html.py`): точная перекодировка через глифы, кластеризация строк с надстрочными, фильтр колонтитулов, склейка переносов, якоря внутри абзаца.
4. **JSON → HTML.** По одному файлу на Item, плюс сводные файлы серий (§5). Для Diplomatic добавляется распознавание зачёркиваний (линия через середину x-высоты), серого цвета (волнистое подчёркивание) и знаков вставок.
5. **Контроль.** Выборочное сравнение с экраном программы и с онлайновым BNE (Wittgenstein Source); подсчёт страниц и якорей по Item List.

Оценка объёма: 12 экранов MS 101 печатаются в 9 страниц PDF примерно за 15 с. Весь корпус в двух версиях — порядка десятков тысяч страниц PDF и примерно сутки машинного времени пакетом. Это экстраполяция, на всём корпусе не проверено. Основной труд — шаг 4 для Diplomatic и разбор особых случаев.

**Риски:** стабильность Folio под Wine на очень больших выделениях (TS 213, 768 стр.), поэтому большие единицы печатаются кусками; около десятка частных глифов OUP/WAB с именами `pNN` нужно опознать один раз визуально (два уже опознаны: `p98` = „, `p71` = “); вёрстка дипломатической версии (вставки над/под строкой, поля) переносится в HTML приближённо.

### Б. Открытые XML TEI от Бергенского архива *(дополнение, а для части корпуса — лучше диска)*

С 2000 года транскрипции перенесены в XML TEI, с единицей «Bemerkung» (`<ab>`), датировками и уточнениями. Это **новее и точнее BEE 2000**.
* **5 000 страниц — CC BY-NC**, свободная загрузка из репозитория CLARINO (UiB).
* **15 000 страниц — ограниченная лицензия** (CLARIN ACA-NC-NORED: академический доступ, без распространения; обновление апреля 2025 г.).
* В сети также доступны HTML-выдача BNE на wittgensteinsource.org и интерактивная IDP на wittgensteinonline.no.

Для единиц из открытого набора разумно брать TEI и не печатать с диска. Для остальных — диск по варианту А, либо запросить доступ к ограниченному набору (он рассчитан на академических пользователей).

### В. Разбор формата NFO напрямую *(не рекомендую)*

Формат проприетарный и сжатый: даже заголовок базы обфусцирован XOR-ом. Публичной спецификации нет. Это недели реверс-инжиниринга 16-битного кода ради результата, который вариант А даёт сейчас.

## 5. Единица «один файл»: что предлагаю

**Базовый слой — один HTML на Item, в двух версиях:** `Ms-101.norm.html`, `Ms-101.diplo.html`.
* Постраничные якоря `#ms101-34v` (как в прототипе) и перекрёстные ссылки N↔D на ту же страницу. Если найдутся Image Discs, туда же идут ссылки на факсимиле `101/…jpg`.
* Шапка с метаданными из Item List (название, датировка, число страниц, место хранения).

**Слой серий — сборные HTML, где связанное собрано в один файл:**

| Серия | Состав | Замечание |
|---|---|---|
| Kriegstagebücher 1914–1916 | MSS 101–103 | Удобно разделить на два потока: философские записи и шифрованный дневник. Нужно проверить, надёжно ли разделение по сторонам листа |
| Bände I–XVIII | MSS 105–122 | Порядок по ходу текста: 105/106 уже так транскрибированы; 107↔108 перемежаются, нужна таблица стыков |
| Bände A–S | MSS 123–138 | |
| Big Typescript | TS 212 → TS 213 (+ 214–215) | Можно ставить рядом с исходными рукописями |
| Blue / Brown Book | TS 309 / TS 310 (+ MS 141, MS 115 II) | |
| Генезис PU | MS 142, TS 220, 221, 227a/b, 228–229, 244–245… | Основа для синоптического просмотра |
| Диктовки Шлику | TS 302–306 | Короткие, естественно в одном файле |

Серии задаются небольшим конфигом (YAML/JSON): список единиц и диапазонов страниц в нужном порядке. Генератор собирает из базового слоя без повторной печати. Для серий с перемежающимся текстом конфиг хранит последовательность диапазонов страниц, а не только список Items.

Если позже нужны ссылки по замечаниям (например, PU §43 ↔ место в рукописи), их даёт только BNE/TEI: в BEE 2000 у замечаний нет собственных идентификаторов. Это ещё один довод сочетать А и Б.

## 6. Правовая сторона (кратко, не юридическая консультация)

Тексты самого Витгенштейна (ум. 1951) — отдельный вопрос. **Слой издания** — транскрипции, нормализация, разметка — защищён правами OUP, Бергенского университета и Wittgenstein Trustees, а лицензия диска рассчитана на личное и научное использование. Печать разрешена самим изданием, и переводить свою распечатку в удобный формат для личной работы разумно. Публиковать полученные HTML или выкладывать их в открытый репозиторий без согласия правообладателей нельзя. Открытый набор TEI идёт под CC BY-NC, его можно использовать некоммерчески с указанием источника.

## 7. Предлагаемый порядок работы

1. Проверить показ скрытого текста при печати; опознать частные глифы `pNN`.
2. Написать пакетную печать по Items (NORM, затем DIPLO), прогнать на 3–5 разнотипных единицах: тетрадь (101), том (107), машинопись с рукописными вставками (213), диктовка (309).
3. Довести конвертер Normalized до продукта: стабильные классы, картинки, метаданные из Item List, индекс.
4. Конвертер Diplomatic: зачёркивания, серое, вставки, перестановки.
5. Конфиг серий и сборка сводных файлов; сверка с BNE на открытой части.

## 8. Что взять из проекта HWPh (`hwph-xml`)

Архитектура HWPh (Markdown → XML-база → XQuery → статическая читалка + сервер + краулер, принцип Eldamo) подходит Nachlass почти целиком. По масштабу корпуса сопоставимы (≈ 20 000 страниц против 13 томов), и связка уже проверена на вашей машине (Win7, Python 3.8, Java 8 x64, Saxon-HE).

**Берётся как есть или почти как есть**

| Из HWPh | Для Nachlass |
|---|---|
| `xq/*.xq` + `split.py`, `manifest.xq`, `crawl.py`, `finish.py`, `server/` | Тот же конвейер; `article.xq` → `item.xq` (страница единицы), `index.xq` и `global.xq` — с другими указателями |
| `static/hwph_ui.html`, `static_api.js`, `i18n.js`, `page.css`, KaTeX | Оболочка читалки: поиск, списки и выборки, пометки и заметки, цветные фильтры, ru/en/de/fr, статические страницы без JS |
| Вид «колонки печатного издания» (`colmap`, линии-разделители) | Границы страниц рукописи (`1r`, `34v`) с переходом к факсимиле и к другой версии. Здесь границы точные, а не приблизительные |
| `lib/hwph_common.py` (свёртка `ß→ss`, умлауты, сниппеты) | Без изменений: немецкий тот же |
| `pdf_tools/glyph_map.json` + `picture_hash` | Битмапы формул и знаков BEE: отпечаток → `sym` / `tex` / `img`, по той же схеме |
| Сборка строк в `hwph2md.py` (`page_lines`: слияние по базовой линии с допуском 0,45·size, срез колонтитула) | Тот же приём, что в моём прототипе. Прототип стоит перевести на PyMuPDF, как в `hwph2md`: он идёт на Py 3.8 и даёт заодно цвета спанов и векторные линии (`get_drawings`) для подчёркиваний и зачёркиваний |
| `epub2md/transfer.py` (выравнивание двух источников по свёрнутым словам через `difflib`, перенос меток) | Два применения: (1) Normalized ↔ Diplomatic — связь не только постранично, но и по абзацам; (2) BEE ↔ BNE TEI — новый текст для 5 000 открытых страниц с сохранением якорей и разметки BEE. Ровно та же схема «гибрида», что epub + PDF |
| `lib/hwph_cite.py`, `persons_fix.json`, `bridge/` | Распознавание лиц (Russell, Frege, Ramsey, Moore…) и сверка с ΦilosΦaira через тот же мост. Позже — перекрёстные ссылки HWPh ↔ Nachlass |
| `compare.py`, `tools/i18n_check.py` | Контроль сборки и перевода без изменений |

**Переделывается**

* **Промежуточный формат.** Для Normalized Markdown хватает: несколько классов `ed` / `alt` / `u` / `i` / `sup` плюс якоря страниц. Дипломатической версии его мало: зачёркивания, `[a|A]`, вставки над/под строкой и на полях, стрелки перестановок, волнистые подчёркивания. Предлагаю для Nachlass писать из PDF сразу XML в словаре, близком к TEI BNE (`<del>`, `<add place="above">`, `<subst>`, `<hi rend="ul">`, `<pb n="34v"/>`). Тогда импорт BNE ложится в ту же схему, а парсер Markdown из `md2xml.py` не нужен; слой XQuery и читалка остаются.
* **Модель данных.** Словарь статей (лемма, автор, колонки, `xrefs`, регистр тома 13, предметные группы) меняется на корпус документов: Item → страница → текст в двух версиях + факсимиле + метаданные из Item List + конфиг серий (§5). Вместо регистра и предметных групп — указатели по типам единиц и датировкам, серии, поля нотаций BEE (Mathematical / Logical / Musical…), лица.
* **Вид статьи** становится параллельным: N | D | факсимиле, с синхронной прокруткой по якорям страниц.
* **Поиск.** Шифрованный текст дипломатической версии исключить из словарного указателя или пометить отдельно; расшифровка есть в Normalized.

**Порядок:** сначала конвертер PDF → XML (на основе прототипа и `hwph2md`), затем `item.xq` на основе `article.xq`, затем перенос оболочки читалки. Выравнивание с BNE и мост к ΦilosΦaira — после того, как база соберётся.

## Приложения

* `probe_ms101.html` — результат прототипа на пробной распечатке начала MS 101 (Normalized, 9 стр. PDF).
* `folio_pdf2html.py` — прототип конвертера: точная перекодировка через имена глифов исходных шрифтов, таблица Adobe Symbol, классы цвета по легенде BEE, подчёркивания, надстрочные, якоря страниц.
* Среда (не прилагается, описана): Wine 9 + `wine32`, ручная установка Folio Bound VIEWS, `[Text Export Filters]` и `[Object Handlers]` в `VIEWS.INI`, CUPS + cups-pdf, Symbol-шрифт с кодировкой Adobe Symbol в `C:\windows\Fonts`.
