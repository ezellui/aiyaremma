# Wittgenstein's Nachlass (BEE 2000) → XML → HTML: что сделано

Итог работы по `Nachlass.iso`. Обе транскрипции, нормализованная (NORM) и дипломатическая (DIPLO), сконвертированы целиком: все 156 единиц хранения (Ms 101–183, Ts 201–245, диктовки 301–310). Получилось по одному XML-файлу на единицу и версию, итого 312 документов. Поверх них:

- **база BaseX** — весь корпус как одна коллекция, запросы на XQuery;
- **статический сайт** — по странице на единицу и версию, 14 страниц-серий, оглавление, страницы для проверки рисунков.

**Правовая оговорка.** Экспорт для пользователя Guest в программе заблокирован. Эту защиту я не снимал: текст получен только разрешённой изданием печатью. Результат годится для личной работы. Распространять его (выкладывать сайт, передавать файлы) можно только с согласия правообладателей: Oxford University Press, The Wittgenstein Trustees, University of Bergen. Поэтому сайт отдаётся архивом и не публикуется по ссылке.

## Что в архивах

- **`bee_site.zip`** — сайт. Открывается `index.html`, сервер не нужен.
  - **Страница единицы:** `items/<n>.norm.html` и `items/<n>.diplo.html`.
    - Под заголовком указаны транскрипторы и корректоры (из ITEM.NFO).
    - Значок страницы — ссылка на ту же страницу в другой транскрипции.
    - Переключатели «Alternativen» и «Personenregister» показывают нерешённые варианты и указатель лиц.
    - Где у записей известен только год (BEE пишет «1 Jan, 1932»), показан год.
  - **Страница проверки рисунков:** `figures/<n>.html`, ссылка «Abbildungen» на странице единицы. Таблица: страница, подпись BEE, картинка; отдельно отмечено, если картинка не перенесена или вставлена перед формулой.
- **`bee_xml.zip`** — 312 XML и `img/` (2 556 картинок). Это основной результат: и сайт, и база собираются из него.
- **`bee_scripts.zip`** — весь конвейер (Python, bash, XQuery).

## Как работать с корпусом: файлы и база

Главный источник — файлы, по одному на единицу и версию. Их можно пересобирать по отдельности, разница видна в git, сайт строится кусками. Для запросов по всему корпусу файлы загружаются в BaseX как одна база `bee`; файлы при этом остаются как есть.

```
apt install basex             # или дистрибутив с basex.org
bee_db.sh /путь/к/xml         # база "bee" с полнотекстовым индексом
basex xq/examples.xq          # примеры: объём, частые лица, полнотекстовый поиск, сверка NORM↔DIPLO
basexgui                      # графическая оболочка; basexhttp — REST и веб-приложения
```

Пример запроса:

```xquery
db:get('bee')/item[@version='norm']//rec[. contains text 'familienähnlichkeit.*' using wildcards]
```

Он находит заметки со словом «Familienähnlichkeit» во всех формах, с номером единицы, страницей и датой. Связка «XML-файлы + база + XQuery» — та же, что в проекте HWPh; читалку и веб-слой оттуда можно подключить к этой базе.

## Модель данных (XML, близкий к TEI)

```
<item n="105" title="Band I …" version="norm|diplo" transcribers="…" proofreaders="…">
  <pb n="43" facs="105/047.jpg"/>                      страница рукописи + имя файла факсимиле (совпадает в NORM и DIPLO)
  <rec page="43" date="6 Feb, 1929">                   запись BEE (заметка) — только в NORM
    <p rend="right|center">…</p>
  </rec>
  <notes><note n="1">Vgl. Faksimile; leere Seite.</note></notes>   всплывающие примечания (DIPLO)
</item>
```

Строчные элементы:

| Элемент | Что означает |
|---|---|
| `<ed>` | редакторская вставка (в издании красная) |
| `<app><rdg/>…<lem/></app>` | нерешённые варианты: последний — `lem` |
| `<person key="…"/>` | указатель лиц |
| `<formula notation="…">` | нотация: логика, математика; индексы — `<hi rend="sub/sup">` |
| `<figure src="img/….png" desc="…"/>` | рисунок или формула, нарисованная картинкой |
| `<figure … place="before-formula"/>` | картинка, стоящая перед формулой (её подпись в A стала меткой формулы) |
| `<figure desc="…" missing="1"/>` | картинка не перенесена; показана подпись в рамке |
| `<del>`, `<hi rend="u/b/i/alt">` | зачёркнутое; подчёркивание, жирный, курсив, вариант |

Только в DIPLO:

| Элемент | Что означает |
|---|---|
| `<lb/>` | конец строки рукописи |
| `<subst><del/><add/></subst>` | замена `[a\|b]` |
| `<add place="interlinear\|inline">` | вставка `«…»` или `‹…›` |
| `<hi rend="code">` | шифр Витгенштейна (Geheimschrift) |
| `<date when=…/>` | дата |
| `<notation key=…/>` | дескриптор |

## Конвейер

### 1. Печать

Folio VIEWS 3.1 работает под Wine (Xvfb) и печатает в CUPS-PDF. Скрипты: `batch_segments2.sh`, `print_sel.sh`, `resume.sh`, `batch_one.sh`.

- В Page Setup включён Hidden Text: так печатаются маркеры записей, даты, страницы, указатель лиц и дескрипторы.
- Текст печатается без обработчика растров: с растрами Folio под Wine падает.
- Метаданные единиц взяты из ITEM.NFO запросом `transcriber*` (`bee_meta.py`). Есть для 154 единиц из 156; у 212 и 242 таких записей нет.

### 2. PDF → XML

`bee_pdf2xml.py` превращает распечатки в XML, `bee_build.py` собирает их по единицам. Символы восстанавливаются по номерам глифов:

- AGL;
- карта шрифтов WAB (333 глифа);
- собственный Symbol;
- растровые Type 3: md5 процедуры отрисовки, общая таблица по всем распечаткам (386 глифов, `t3_auto.json`) и 85 глифов, определённых вручную (`glyphs3.json`).

**Итог: 0 неопознанных символов в обеих версиях.**

### 3. Рисунки — снимаются с экрана

Печатью растры не получить: через CUPS палитра пустая, а «печать в файл» на части записей роняет Folio. На экране же Folio рисует их правильно.

1. Запрос выделяет нужные записи, режим «Records With Hits» оставляет в окне только их.
2. Фон окна в реестре Wine сменён на светло-жёлтый, поэтому растр виден как непрозрачный белый прямоугольник.
3. `fig_capture.py` и `fig_chunks.sh` листают окно порциями по 50 записей (до трёх Folio параллельно) и вырезают картинку справа от подсвеченного дескриптора.
4. Снятые картинки сопоставляются с текстом по длине дескрипторов: моноширинный шрифт на экране даёт 8 px на знак плюс 16 px. Сопоставление идёт динамическим программированием в полосе.

| Проход | Запрос | Записей | Сопоставление | Результат |
|---|---|---|---|---|
| Рисунки | Graphics, Tables, Music | 1 526 | `bee_figs2.py` | 2 640 картинок по местам |
| Формулы-картинки | Mathematics, Logic, Set Theory, Notation | 5 068 | `bee_figs3.py` | ещё ≈1 000 картинок; около 870 ложных мест рисунка, за которыми был обычный текст, убраны |

`bee_figs3.py` сверяет каждый дескриптор, а не только картинки. Перед формулой картинка вставляется лишь в надёжных случаях (`place="before-formula"`).

**Итог NORM:** 3 695 картинок на местах, 531 место осталось подписью.

**DIPLO:** те же картинки перенесены по дескриптору и странице факсимиле (`bee_figs_diplo.py`) — 3 107.

### 4. HTML и база

`bee_xml2html.py` и `bee_site.py` собирают сайт (список серий — `series.json`), `bee_db.sh` — базу, `xq/examples.xq` — примеры запросов.

## Что осталось

- **531 место рисунка в NORM** без картинки: на экране её не нашлось или сопоставление было ненадёжным. Они видны на страницах `figures/<n>.html`.
- **Сопоставление статистическое.** Изредка картинка может оказаться у соседнего места. Среди формул-картинок проскакивают крошечные текстовые фрагменты (одна буква в рамке).
- **Ошибки символов в отдельных формулах.** Например, в Ms 107, запись 101: вместо символов «Ô», «Ó», «Í». Глиф опознан, но, видимо, не тем знаком.
- **Сверки NORM↔DIPLO по записям нет**, только по страницам: ссылки на сайте и общий `pb/@facs` в базе. В дипломатической распечатке нет маркеров записей.
