# Анализ проблемы визуализации комплексных функций в режиме Доменной карты

## Выявленная проблема

В визуализаторе комплексных функций обнаружена проблема: в режиме Доменной карты корректно отображаются только функции `z^2` и `1/z`, а другие функции (`sin(z)`, `exp(z)` и т.д.) не вычисляются должным образом, хотя в остальных режимах визуализации всё работает нормально.

## Причина проблемы

Корневая причина в том, что для рендеринга Доменной карты используется **Web Worker**, который должен вычислять значения комплексных функций в отдельном потоке. Однако внутри Web Worker реализовано корректное вычисление только для двух конкретных функций:

```javascript
// Очень упрощенная версия расчета для часто используемых функций
if (functionStr === 'z^2') {
    result = {
        re: z.re * z.re - z.im * z.im,
        im: 2 * z.re * z.im
    };
} else if (functionStr === '1/z') {
    const denom = z.re * z.re + z.im * z.im;
    result = {
        re: z.re / denom,
        im: -z.im / denom
    };
} else {
    // Для других функций используем простую реализацию
    result = {re: re, im: im};
}
```

Для всех остальных функций в ветке `else` вместо вычисления значения функции возвращаются координаты исходной точки (`{re: re, im: im}`), что эквивалентно функции `f(z) = z`, и поэтому мы не видим нормальной визуализации.

Основная проблема в том, что Web Worker не имеет доступа к библиотеке `math.js`, которая используется в основном коде для вычисления комплексных функций через функцию `evaluateFunction()`.

## Решение проблемы

Существует два подхода к решению:

### Вариант 1: Реализовать основные комплексные функции в Web Worker

Это наиболее полное решение, но требует реализации парсера выражений и функций работы с комплексными числами.

### Вариант 2: Использовать запасной механизм рендеринга вместо Web Worker

В коде уже есть запасной вариант рендеринга, который вызывается, если Web Workers не поддерживаются. Этот блок кода использует функцию `evaluateFunction()`, которая корректно вычисляет комплексные функции с помощью библиотеки `math.js`. 

Поскольку Вариант 2 проще в реализации, далее приведено решение на его основе.

## Детальное исправление

Нужно изменить функцию `renderDomainColoring()`, чтобы она всегда использовала запасной механизм рендеринга без Web Worker.

Найдите функцию `renderDomainColoring()` (примерно строки 2132-2300) и замените её на следующий код:

```javascript
// Рендеринг доменной окраски с оптимизацией
function renderDomainColoring() {
    // Показываем индикатор загрузки
    document.getElementById('loading').style.display = 'flex';
    
    // Запасной вариант, который теперь стал основным
    setTimeout(() => {
        const width = domainCanvas.width;
        const height = domainCanvas.height;
        const imageData = domainCtx.createImageData(width, height);
        const data = imageData.data;
        
        // Размер шага для вычисления значений
        const stepSize = 1 / viewScale;
        
        // Верхняя левая точка видимой области в комплексной плоскости
        const startRe = -width / (2 * 100 * viewScale) - viewOffsetX;
        const startIm = height / (2 * 100 * viewScale) - viewOffsetY;
        
        // Итерация по всем пикселям с шагом для ускорения
        // При более низком качестве рендерим с меньшим разрешением
        const pixelSkip = qualityLevel === 'low' ? 2 : 1;
        
        for (let j = 0; j < height; j += pixelSkip) {
            for (let i = 0; i < width; i += pixelSkip) {
                // Преобразуем координаты пикселя в комплексную плоскость
                const re = startRe + i * stepSize / 100;
                const im = startIm - j * stepSize / 100;
                
                try {
                    // Вычисляем значение функции
                    complexCache.z.re = re;
                    complexCache.z.im = im;
                    const w = evaluateFunction(complexCache.z);
                    
                    // Получаем аргумент и модуль
                    const arg = math.arg(w);
                    const mag = math.abs(w);
                    
                    // Преобразуем в цвет
                    const hue = ((arg + Math.PI) / (2 * Math.PI)) * 360;
                    const norm = 2 * (Math.atan(mag / 2) / Math.PI);
                    const sat = 80 + 20 * Math.sin(norm * Math.PI * 2);
                    const light = 60 - 30 * Math.cos(norm * Math.PI);
                    
                    // Преобразуем HSL в RGB
                    const rgb = hslToRgb(hue / 360, sat / 100, light / 100);
                    
                    // Дублируем пиксели при низком качестве
                    for (let dy = 0; dy < pixelSkip; dy++) {
                        for (let dx = 0; dx < pixelSkip; dx++) {
                            if (j + dy < height && i + dx < width) {
                                // Индекс в массиве данных изображения
                                const idx = ((j + dy) * width + (i + dx)) * 4;
                                
                                // Устанавливаем RGBA значения
                                data[idx] = rgb[0];
                                data[idx + 1] = rgb[1];
                                data[idx + 2] = rgb[2];
                                data[idx + 3] = 255; // Альфа-канал
                            }
                        }
                    }
                } catch (e) {
                    // Ошибка при вычислении
                    for (let dy = 0; dy < pixelSkip; dy++) {
                        for (let dx = 0; dx < pixelSkip; dx++) {
                            if (j + dy < height && i + dx < width) {
                                const idx = ((j + dy) * width + (i + dx)) * 4;
                                data[idx] = 0;
                                data[idx + 1] = 0;
                                data[idx + 2] = 0;
                                data[idx + 3] = 255;
                            }
                        }
                    }
                }
            }
        }
        
        // Отрисовка изображения
        domainCtx.putImageData(imageData, 0, 0);
        
        // Рисуем критические точки
        if (settings.showCriticalPoints) {
            drawCriticalPointsOnDomain();
        }
        
        // Скрываем индикатор загрузки
        document.getElementById('loading').style.display = 'none';
    }, 50);
}
```

## Альтернативное решение (для специалистов)

Если требуется сохранить использование Web Worker для улучшения производительности, необходимо реализовать внутри Worker парсер выражений и основные комплексные функции. Это сложнее, но вот общий подход:

1. Определить внутри Web Worker базовые операции с комплексными числами (сложение, умножение, деление и т.д.)
2. Добавить реализации основных функций (sin, cos, exp, log, sqrt)
3. Реализовать простой парсер выражений или использовать упрощенную версию интерпретатора

Это потребует существенной доработки кода Web Worker и может быть рекомендовано только при наличии достаточных навыков программирования и времени на реализацию.

## Дополнительные рекомендации

1. Для функций, требующих интенсивных вычислений, может потребоваться дополнительная оптимизация:
   - Увеличение шага при отрисовке (уменьшение разрешения)
   - Кэширование результатов вычислений
   - Адаптивный уровень детализации в зависимости от масштаба

2. Можно добавить переключатель между режимами рендеринга (с использованием Worker и без) для опытных пользователей.

3. При работе с более сложными функциями стоит добавить обработку краевых случаев, таких как полюсы, разрывы и особые точки.
