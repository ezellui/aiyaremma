# Перевод содержимого Eldamo на русский язык

Этот документ описывает русскую базу перевода и инструменты для работы с ней:

- `make` создаёт заготовку базы;
- `task` выдаёт задание на перевод;
- `apply` вносит переведённое задание в базу;
- `check` находит непереведённое и подозрительное;
- `sync` и `prune` служат для обслуживания базы.

Перевод интерфейса (меню, заголовки, подписи) устроен отдельно, через каталог `src/main/webapp/config/messages/messages-ru.xml`. Здесь речь только о содержимом словаря.

## Что переводится

| Что | Где в английской базе | Как хранится в русской базе |
|---|---|---|
| Глоссы слов | `word/@gloss`, `word/@ngloss` | таблица `gloss`: английская строка → перевод (общая для всех слов с таким глоссом) |
| Индивидуальный глосс | то же | раздел `overrides`: перевод для одной страницы (page-id), если общий не подходит |
| Заголовки статей грамматики, фонетики и текстов | `@v` у слов с `speech` = grammar, phonetic-rule, phonetic-group, text | таблица `title` |
| Редакторские пометы | текст элементов related, change, correction, deriv, inflect, element, cognate, before (например, `[related to]`, `[archaic]`) | таблица `phrase` |
| Названия | `cat/@label`, `cat-group/@label`, `language/@name`, `language-cat/@name` | таблица `label` |
| Заметки | `word/notes`, разделы языков (notes, words, vocabulary, neologisms, deprecations, grammar, phonetics, names, phrases, roots), `source/notes` | раздел `notes`, по сегментам |

Не переводятся:

- цитаты из источников (`ref` и его `@gloss`) и примечания к цитатам (`ref/notes`);
- формы слов.

Старые русские глоссы английской базы не используются.

### Сегменты заметок

Заметка делится на сегменты, и каждый сегмент переводится отдельно:

- `lead` — первый абзац;
- `main` — остальной текст до первого раздела с заголовком;
- разделы с заголовком вида `<p><b>Conceptual Development:</b>` (`Neo-Quenya`, `Possible Etymology` и т. п.). Повторный заголовок получает суффикс: `Neo-Quenya#2`.

У каждого сегмента в базе хранятся:

- английский текст, с которого сделан перевод;
- его хэш (без учёта пробелов и переносов строк).

Если английский текст сегмента потом изменится, сайт покажет этот сегмент по-английски, пока перевод не обновят. Остальные сегменты заметки останутся русскими.

## Русская база: `src/data/eldamo-data-ru.xml`

```xml
<l10n lang="ru" base-version="0.8.13" snapshot="b1a0d156d8ff58a6" synced="...">
  <snapshot> ... </snapshot>                 снимок английской базы на момент последней синхронизации
  <table name="gloss">
    <e en="king">король</e>
    <e en="queen"/>                            известная, но ещё не переведённая строка
  </table>
  <table name="title"> ... </table>
  <table name="phrase"> ... </table>
  <table name="label"> ... </table>
  <overrides>
    <gloss page-id="1369821233" en="mother">мама</gloss>
  </overrides>
  <notes>
    <n owner="word" id="1176346759" part="notes" seg="lead" hash="...">
      <en><![CDATA[<p>English text</p>]]></en>
      <ru><![CDATA[<p>Перевод</p>]]></ru>
    </n>
  </notes>
</l10n>
```

Раздел `snapshot` ведут инструменты, его не нужно править руками. Переводы можно править прямо в этом файле, но удобнее работать через задания.

Особые значения перевода:

- пустой перевод означает «не переведено», и сайт показывает английский текст;
- `=` означает, что перевод совпадает с английским (например, имя собственное или латинское название). Проверка такой перевод не отмечает.

На сайте переведённый глосс выводится в кавычках «ёлочках», непереведённый остаётся английским в “лапках”. Так сразу видно, что ещё не переведено.

## Как запускать

Через Gradle, из корня проекта:

```
gradle l10n "-Pargs=help"
gradle l10n "-Pargs=task --out task-ru.xml"
```

Или напрямую, после сборки (`gradle classes`):

```
java -cp build/classes/java/main xdb.l10n.L10n task --out task-ru.xml
```

Пути по умолчанию:

- `--en src/data/eldamo-data.xml`;
- `--base src/data/eldamo-data-ru.xml`.

В `-Pargs` аргументы разделяются пробелами, поэтому пути с пробелами лучше передавать через запуск `java`.

На Windows консоль может не показать часть символов. Отчёт проверки можно записать в файл: `check --report report.txt`. Файл будет в UTF-8.

## Порядок работы

### 1. Заготовка (один раз)

```
gradle l10n "-Pargs=make"
```

Команда создаёт `src/data/eldamo-data-ru.xml` и заносит в него все переводимые строки с пустым переводом. Названия языков берутся из каталога интерфейса `messages-ru.xml`, чтобы не переводить их дважды. Заметки в заготовку не попадают: они появляются в базе по мере перевода.

Если базу нужно создать заново, добавьте `--force`. Существующий перевод при этом будет потерян.

### 2. Задание на перевод

Новое и изменённое после последней синхронизации:

```
gradle l10n "-Pargs=task --out task-ru.xml"
```

Всё непереведённое, порциями:

```
gradle l10n "-Pargs=task --scope all --kinds gloss --limit 1000 --out gloss-1.xml"
gradle l10n "-Pargs=task --scope all --kinds notes --notes lead --langs q,s --limit 200 --out notes-1.xml"
```

Параметры:

- `--scope delta|all`:
  - `delta` (по умолчанию) — новые строки, изменённые заметки и устаревшие переводы;
  - `all` — ещё и всё, что известно, но не переведено. В режиме `all` заметки включаются только явно, через `--kinds ...,notes`: их очень много.
- `--kinds gloss,title,phrase,label,notes` — что включать.
- `--notes lead,main,cd,neo,other` — какие сегменты заметок включать:
  - `cd` — Conceptual Development;
  - `neo` — Neo-Quenya, Neo-Sindarin и т. п.;
  - `other` — прочие разделы.
- `--owners word,language,source` — заметки слов, разделы страниц языков или заметки источников.
- `--langs q,s,...` — только то, что относится к этим языкам.
- `--limit N` — не больше N единиц. Сначала идут изменённые, затем новые, затем непереведённые; строки упорядочены по частоте употребления.

В начале задания перечислены:

- добавленные страницы;
- удалённые страницы;
- изменённые страницы, со списком изменений вида `gloss: old → new`;
- изменённые языки и источники.

Это справочная часть, переводить её не нужно.

### 3. Перевод задания

Каждая единица выглядит так:

```xml
<item kind="gloss" status="new" en="mother, mum">
  <use ctx="1369821233" l="ad" v="ammê"/>          где встречается (до трёх примеров)
  <hint page-id="1369821233" old-en="mother">мать</hint>   прежний перевод, если глосс этой страницы изменился
  <ru></ru>                                         ← перевод сюда
</item>
```

Правила:

- Перевод пишется в `<ru>`. Если оставить его пустым, строка останется непереведённой.
- Сохраняйте пометы: `*` (реконструкция), `?` (под вопросом), `⚠️`, `†`, `‽`, `[…]` (редакторские добавления), `{…}`, метки языков вида `[ᴹQ.]`. Вместо `(lit.)` можно писать `(букв.)`.
- Если для одной страницы нужен другой перевод глосса, добавьте в единицу `<override page-id="...">перевод</override>`.
- `kind="gloss-override"` значит, что у страницы с индивидуальным переводом изменился английский глосс. Новый перевод пишется в `<ru>`. Если оставить его пустым, индивидуальный перевод будет удалён, и страница получит общий перевод из таблицы.
- Заметки (`kind="notes"`) — это HTML внутри CDATA. Переводите текст и сохраняйте разметку:
  - `<p>`, `<b>`, `<i>`;
  - ссылки `<a l="..." v="..."/>` (их атрибуты не трогать);
  - ссылки на источники вида PE17/72;
  - эльфийские слова в `<i>`.
- У изменённой заметки (`status="changed"`) есть элементы:
  - `<en>` — новый английский текст;
  - `<old-en>` — прежний английский текст;
  - `<old-ru>` — прежний перевод.

  В `<ru>` заранее подставлен прежний перевод: его нужно поправить по разнице между `old-en` и `en`.
- Элементы `<orphan>` в конце задания — переводы того, чего больше нет в английской базе. Это справка, переводить их не нужно.

Файл задания — UTF-8. Блокнот Windows и другие редакторы, которые добавляют метку BOM, подходят.

### 4. Проверка задания

```
gradle l10n "-Pargs=check --task task-ru.xml --report report.txt"
```

Проверка находит:

| Код | Что значит |
|---|---|
| `empty` | не переведено |
| `same` | перевод совпадает с английским (если так и задумано, напишите `=`) |
| `latin` | в переводе нет ни одной русской буквы |
| `fragment` | в переводе остались английские фрагменты: три английских слова подряд или два со служебным словом (the, of, and…). Эльфийские формы в `<i>`, ссылки, сокращения источников и метки языков не учитываются |
| `markers` | не совпадают пометы `* ? ⚠️ † ‽ […] {…} (lit.)` и метки языков |
| `html` | нарушена разметка |
| `links` | не совпадают ссылки на статьи |
| `refs` | не совпадают ссылки на источники |
| `not-updated` | оригинал изменился, а перевод оставлен прежним |

`--list N` задаёт число примеров на каждый вид замечаний (по умолчанию 20; `-1` — все).

`--fail` завершает команду с кодом 1, если замечания есть.

### 5. Внесение задания

```
gradle l10n "-Pargs=apply --task task-ru.xml"
```

- Непустые переводы вносятся в базу.
- Пустые переводы новых строк регистрируются как известные, но непереведённые. Такие строки потом выдаёт `task --scope all` и находит `check`.
- `--dry-run` показывает, что будет сделано, но ничего не записывает.

Снимок английской базы обновляется, только если задание полное: `--scope delta`, без фильтров и ограничений, и сделано от текущего состояния русской базы. В остальных случаях снимок остаётся прежним, и следующее задание `delta` снова покажет те же изменения страниц. Чтобы принять текущую английскую базу как синхронизированную без задания, есть команда `sync`.

### 6. Проверка всей базы

```
gradle l10n "-Pargs=check --report report.txt"
```

Проверяются все переводы базы теми же правилами. Сравнение с английской базой дополнительно находит:

| Код | Что значит |
|---|---|
| `missing` | новые строки, которых ещё нет в русской базе |
| `stale` | заметки и индивидуальные глоссы, у которых изменился английский оригинал |
| `orphan` | переводы того, чего больше нет |

В конце отчёта печатается покрытие перевода по таблицам и видам заметок.

С `--en none` проверяется только сама русская база.

### 7. После обновления английской базы

1. Положите новый `eldamo-data.xml` в `src/data`.
2. Выполните `task`. Получите задание на всё новое и изменённое.
3. Переведите задание, проверьте его и внесите (`check`, `apply`).
4. При желании удалите переводы исчезнувших строк: `prune` (есть `--dry-run`). Их перечисляет раздел `<orphan>` задания.

### 8. Показ на сайте

Сайт читает базу из каталога данных приложения: `src/main/webapp/data/eldamo-data-ru.xml`. Туда она попадает вместе с остальными данными при копировании `src/data` (см. README). После `apply` скопируйте файл ещё раз:

```
cp src/data/eldamo-data-ru.xml src/main/webapp/data/          (Linux)
Copy-Item src\data\eldamo-data-ru.xml src\main\webapp\data\   (Windows PowerShell)
```

Перезапускать сервер не нужно: изменённый файл подхватывается в течение пары секунд.

Перевод показывается на страницах с префиксом `/ru/`. Если файла базы нет, содержимое остаётся английским.

## Где это в коде

- `src/main/java/xdb/l10n/`:
  - `L10n` — команды;
  - `EnglishBase` — чтение английской базы;
  - `RuBase` — русская база;
  - `TaskFile` — задание;
  - `Notes` — сегменты заметок;
  - `Checks` — проверки;
  - `L10nStore` — переводы для сайта.
- `xdb.dom.CustomFunctions`: функции `xdb:l10n`, `xdb:l10nGloss`, `xdb:l10nNotes` для запросов.
- `common.xq`, раздел «Content translation»:
  - `c:tr`, `c:label`, `c:tr-gloss`, `c:word-title`, `c:phrase`, `c:notes-text`;
  - вывод глоссов в `c:print-gloss`, `c:print-neo-gloss`, `c:print-gloss-no-space`.
