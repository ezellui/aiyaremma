# HWPh: Markdown → XML-база → XQuery → читалка

Читалка «Historisches Wörterbuch der Philosophie», собранная по принципу Eldamo: тома в Markdown
переводятся в одну XML-базу, а все файлы читалки (страницы статей, данные для поиска, указатели)
порождают XQuery-файлы. SQL-базы, `hwph_build.py`, `hwph_serve.py` и `hwph_export.py` здесь больше нет.

```
Bd01.md … Bd13.md, extras.json, img/   ──md2xml.py──▶  hwph-data.xml  ──xq/*.xq──▶  папка читалки
                                                                                     └─ manifest.json ──▶ crawl.py
```

## Что нужно

* **Python 3.8+** (подходит последний Python для Windows 7, 3.8.x), только стандартная библиотека.
* **Java 8+, 64-разрядная** (32-разрядной не хватит памяти: нужно `-Xmx3g`). Подойдёт Temurin 8 x64,
  установленный для Eldamo.
* **Saxon-HE** уже лежит в `saxon/` (11.7, лицензия MPL 2.0, см. `saxon/notices`). Подходит и 9.9, и 10.
* Память: пик около 2,5 ГБ (Java) — на машине с 8 ГБ хватает.

## Сборка

Windows:
```
build_site.cmd D:\HWPh\HWPh_epub D:\HWPh\site
```
Linux:
```
./build_site.sh ~/HWPh/HWPh_epub ~/HWPh/site
```
Рядом с папкой читалки появится XML-база `site.xml`. Открыть читалку: `site\index.html` (прямо с диска).

Настройки — переменные окружения: `PYTHON`, `JAVA`, `SAXON` (classpath), `XMX` (куча Java, 3g),
`PARTS` (на сколько групп делится словарный указатель, 8), `UI_LANG` (язык страниц статей, ru), `DB`.

Шаги и время (замер на облачной машине, 2 ядра; Java 8, Saxon-HE 11.7):

| шаг | что делает | время | пик памяти |
|---|---|---|---|
| 1. `md2xml.py` | MD → `hwph-data.xml` (181 МБ) | ~55 с | 0,7 ГБ |
| 2. `xq/article.xq` | `data/a`, `data/t`, `pages/<id>.html` (11 190 файлов) | ~110 с | 1,5 ГБ |
| 3. `xq/index.xq` | словарный и позиционный указатель, `vocab.js`, `meta.js` | ~300 с | 2,5 ГБ |
| 4. `xq/global.xq` | регистр, граф, лица, списки, оглавление, `index.html` | ~20 с | 1,8 ГБ |
| 5–6. | неизменные файлы, `xq/manifest.xq`, проверка `finish.py` | ~10 с | |

Итого около 8 минут; читалка — 15 032 файла, 367 МБ.

## Файлы

| файл | назначение |
|---|---|
| `md2xml.py` | разбор Markdown-томов и запись XML-базы (бывший `hwph_build.py`, без SQL) |
| `lib/hwph_common.py`, `lib/hwph_cite.py` | свёртка знаков для поиска, распознавание цитируемых лиц (без изменений) |
| `lib/persons_fix.json`, `lib/img_svg/` | ручные решения по лицам, векторные версии рисунков (без изменений) |
| `xq/common.xq` | общее: свёртка и слова, ключ орфографии, base36, JSON-раскладка, сериализатор HTML |
| `xq/article.xq` | карточка статьи (`data/a`), её тексты (`data/t`), страница статьи (`pages/<id>.html`) |
| `xq/index.xq` | `data/s`, `data/p`, `data/pdir.js`, `data/vocab.js`, `data/meta.js` |
| `xq/global.xq` | `data/r`, `graph.js`, `persons.js`, `data/pat`, `authors.js`, `extras.js`, `pages/index.html`, `index.html` |
| `xq/manifest.xq` | `manifest.json` — все файлы читалки |
| `static/` | неизменная часть читалки: `hwph_ui.html`, `i18n.js`, `static_api.js`, `katex/`, `page.css` |
| `split.py` | раскладывает вывод XQuery по файлам (строка `@@FILE@@ путь` начинает файл) |

| `crawl.py` | собирает читалку с сервера по `manifest.json` |
| `compare.py` | сверка с эталонной читалкой: байты → JSON → DOM |

## XML-база

Корень `<hwph>`; в нём `<articles>` (каждая статья: атрибуты, авторы, оглавление, тело как XHTML в
`<html>`, простой текст трёх частей в `<plain>`, начала колонок в `<colmap>`), `<xrefs>`, `<register>`,
`<persons>`, `<cites>`, `<mentions>`, `<sgroups>`, `<abbrevs>`, `<article-list>`, статистика и знаки
в `<json>`, таблицы свёртки `<fold>`, `<nonword>`, `<rawsep>`. Словарного указателя в базе нет: его
строит `index.xq`. Тело каждой статьи — корректный XML (это проверяется при записи).

## Кравлер

Страницы ссылаются друг на друга, но большинство файлов данных читалка загружает по вычисленным
именам (указатель — по первым буквам слова), поэтому ссылками их не найти. Их перечисляет
`manifest.json`; `crawl.py` берёт его и скачивает все файлы, затем проверяет, что ни одна ссылка
страниц не ведёт мимо списка:

```
python -m http.server 8000 --directory site        (в одном окне)
python crawl.py http://127.0.0.1:8000/ site-copy   (в другом)
```
15 032 файла собираются за 15 секунд; копия совпадает с оригиналом побайтно.

## Отличия от прежней читалки

Сверка с выводом `hwph_export.py` (`compare.py`): совпадают побайтно весь поисковый указатель
`data/s`, `vocab.js`, все тексты `data/t`, регистр, лица, графы, списки, `index.html`, оглавление
страниц, 3553 карточки и 3555 страниц статей; ещё 36 карточек и 36 страниц совпадают как DOM (только
порядок объявлений `xmlns` в SVG). Расходятся намеренно:

1. **Разметка внутри абзаца (138 статей).** Прежний разбор `*…*`, `**…**`, `^…^`, `~…~` регулярными
   выражениями терял звёздочки самого текста (`42*`, `(*)`, `*R*`), растягивал курсив на чужой текст
   и в 24 абзацах (21 статья) давал даже некорректный HTML (`<sup><i></sup>…</i>`). Новый разбор
   строит дерево: верхний/нижний индекс — контейнер, курсив и полужирный парятся как в CommonMark,
   лишняя звёздочка остаётся звёздочкой. Проверено по самому epub: из 235 431 абзаца с такими
   знаками прежний разбор ошибался в 331, новый — в 11 (из них 6 — курсивна ли звёздочка после
   курсивной буквы). Ни одного абзаца, где прежний был прав, а новый ошибся.
2. **Стрелка внутри ссылки (статьи 2511, 2578, 2991).** «→ ‹Gestalt-P., → Gestalttheorie›» — две
   ссылки, а не одна с управляющим знаком в тексте: в графе ссылок на 4 больше (8219).
3. **Повторный `role` в SVG (статья 96)** — убран (браузер и так брал первый).
4. **Поиск фраз, NEAR и с учётом регистра** больше не ограничен 1500 статьями. Прежняя читалка,
   открытая с диска, проверяла фразу по текстам статей и читала не больше 1500 из них
   («проверены 1500 самых вероятных»). Теперь проверка идёт по позиционному указателю `data/p`
   (где стоит каждое слово и как оно написано), для всех статей. Результаты совпадают с полной
   проверкой по текстам (75 запросов из 76 одинаковы; в одном — регистр + подстановка, где список
   слов обрезан на 300 — теперь находятся ровно слова списка). «"der Begriff"» — 1815 статей.
5. `meta.js`: число ссылок (п. 2) и время сборки.
