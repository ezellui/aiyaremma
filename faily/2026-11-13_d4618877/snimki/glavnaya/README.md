## Раскладка (как в издании 2023)

Правило родителя: у n.m1 родитель n.m — отбросить последнюю цифру, затем хвостовые нули
(2.0121 → 2.012; 2.01 → 2; 3.001 → 3; 6.1203 → 6.12). Дети одного узла делятся на группы
по числу отброшенных нулей: у 3 это {3.001}, {3.01–3.05}, {3.1–3.5}.

Порядок вывода: блок корня 1–7 → для каждого раздела: заголовок, затем для каждой группы
детей узла N — **повтор N** и члены группы, потом вглубь поддеревья этих членов, потом
следующая группа. Алгоритм — `work/tlp_tree.py` (`layout`, `expected_sequence`).

Проверено: последовательность номеров, порождённая алгоритмом, совпала с изданием 2023
**построчно** (все 526 номеров). Найденные отклонения — ошибки набора самого издания:
- 3.342, 3.41, 5.46 — повтор-заголовок набран не жирным; 6.23 — член ветви набран жирным;
- 5.5321 стоит прямо в ветви 5.532, без собственного блока.
В результатах раскладка порождена алгоритмом, т. е. эти места выправлены.

В Markdown: повтор узла — жирной строкой, члены ветви — обычной строкой `2.011. …`;
раздел — заголовком `## 2. …`. JSON содержит узлы (`num`, `parent`, `child_groups`, `text`,
комментарии) и саму раскладку (`layout`) — удобно для HTML-читалки.

## Что сделано по каждому тексту

**2023 (Королев)** — 526/526 положений. Канонический текст положения — его первое вхождение
(вхождение членом в ветвь родителя); сноски, стоящие только в жирных повторах, перенесены
туда. Сохранены курсив, абзацы, таблицы (моноширинно, по координатам), надчёркивания (p̄, ξ̄),
ударения. Сноски: `[^N]` — концевые примечания переводчика (все 47 извлечены и приложены
в конце файла), `[^pNN]` — подстрочные со стр. NN. Формулы 4.27 и 4.42 восстановлены вручную
по картинке (LaTeX `$…$`), битые глифы ♯ ♭ ⊢ η̄ заменены. Предисловие, посвящение, эпиграф — в начале.

**2005 (Руднев)** — 518 положений + 407 комментариев. Комментарий выводится цитатой сразу после
положения; если он относится к нескольким положениям подряд — после последнего, с пометкой
«к a–b» (53 таких совместных комментария пересекают границы ветвей — они стоят после последнего
положения своей пачки). Предисловие и комментарий Руднева к заглавию/посвящению/эпиграфу/предисловию — в начале.
Особенности самого издания: **нет** положений 2.182, 3.142, 4.062, 4.063, 4.43, 4.431, 5.1363,
5.5303 (в дереве помечены «в издании 2005 г. отсутствует»); 2.06 напечатано не на месте (среди
2.03x) — в дереве стоит по номеру; опечатки «2.1» (стр. 24, = 2.01), «3.18» (стр. 72, = 3.318),
«6. 371» исправлены. В 6.01 издание печатает [r̄, ξ̄, N(x̄)] — оставлено как есть.
Таблица 4.31, свёрстанная внутри комментария, перенесена в положение. Формулы 4.27, 4.42 и
шапка таблицы 4.442 — вручную.

**1961 (немецкий и английский)** — по 526/526 положений. Номера восстановлены так:
номер ищется в левой колонке; колонка дополнительно перераспознаётся только цифрами
(tesseract, `0123456789.`), а затем найденные начала выравниваются с каноническим списком
(Нидлман—Вунш), так что даже искажённые номера встают на место. Переносы склеены по словарю,
собранному из самого текста; 47 нем. и 12 англ. слипшихся слов («Weltkann», «nureine»)
расклеены по служебным словам. Сноски Огдена/автора (к 1 и к 6.32) приложены.

## Что осталось сделать

1. **Формулы и таблицы 1961 — главное.** Прозу tesseract читает хорошо, а формулы — плохо:
   ξ → £/€, Ω → Q/D, курсивные p/q → Z/¢/g, немецкое «~» → «=»; таблицы 4.31, 4.442, 5.101
   и схемы 6.1203 практически потеряны. Я уже сверил по скану и подготовил тексты для
   4.27, 4.42, 4.31, 4.442, 5.101, 5.502, 5.51, 6, 6.001, 6.01, 6.02, 6.03, 6.241 (нем. и англ.) —
   **но в `build_all.py` они ещё не внесены** (на этом работа прервалась). Дальше — безопасные
   автозамены (£/€ → ξ; нем. «=» перед p/q/( → «~») и вычитка остальных формульных мест
   (3.333, 4.1272–4.1273, 4.24, 5.242, 5.2522, 5.501, 5.52–5.532, 6.1201, 6.1203 и др.).
2. **Вычитка 1961.** `work/qa61.py` по словарю отмечает подозрительные положения:
   189 нем., 129 англ. (список с ошибочными словами — `work/qa61.json`; страница скана каждого
   положения — `work/lp1961.json → pages`). Много ложных срабатываний (старая орфография
   «ausserhalb», сложные слова), но настоящие слипания и ошибки тоже там.
   Разрядка (нем. выделение) и курсив при OCR потеряны — восстанавливать только вручную.
3. **Схемы 6.1203** во всех изданиях — графика, в текстовом слое её нет; в 2023 поставлены
   пометки-заглушки, в 2005 остались обрывки букв И/Л, в 1961 — мусор.
4. **Мелочи:** в 2005 положения с собственными таблицами Руднева в комментариях стоит
   просмотреть (4.442); в 2023 подстрочная «*» к положению 1 и сноска [^10] обе висят на «1»
   (в книге первая — в корневом блоке, вторая — в заголовке раздела).
5. Если нужно — HTML-читалка (сворачиваемое дерево, параллельные колонки текстов) по JSON.

## Как пересобрать

Нужны: Python 3, `pymupdf`, `pyspellchecker`, `pillow`; для 1961 — `tesseract` с `deu`, `eng`.
Положите три PDF в `src/` рядом с `work/` (пути в командах — относительно `work/`).

```bash
cd work
python3 parse_2023.py "../src/Логико-философский трактат (2023).pdf" ru2023.json   # + сверка порядка
python3 check23.py                                   # расхождения издания 2023 с алгоритмом
python3 parse_2005.py "../src/Логико-философский трактат (2005).pdf" ru2005.json
# 1961: растр и OCR (уже сделано — результаты в ../ocr; занимает ~10 мин)
#   pdftoppm -f 25 -l 189 -r 300 -gray "../src/Tractatus ... (1961).pdf" ../ocr/pg
#   ls ../ocr/pg-*.pgm | xargs -P2 -n1 ./ocr1.sh
#   (перераспознанию колонки номеров нужны .pgm — без них используется кэш lp1961.json.numcache.json)
python3 parse_1961.py ../ocr canon.json lp1961.json
python3 build_all.py                                 # → ../out/*.md, *.json
python3 qa61.py                                      # список для вычитки 1961
```

Модули: `tlp_tree.py` — нумерация и раскладка; `pdfline.py` — строки PDF со стилями span-ов,
таблицы; `dehyph.py` — склейка переносов; `wordsplit.py` — расклейка слов; `render_tree.py` —
Markdown/JSON; `build_all.py` — нормализация, ручные правки (`fix(...)`), сборка.
Отладочные: `dump_spans.py`, `grep05.py`, `dbg61.py`, `crop61.py`.
