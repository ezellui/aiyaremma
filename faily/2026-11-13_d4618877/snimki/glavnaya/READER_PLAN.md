# Читалка «Логико-философского трактата»: замысел и план

Решение (14.11.2026): **самостоятельная одностраничная HTML-читалка** — один файл, данные внутри,
открывается с диска двойным щелчком, без сервера. Встраивание в будущую общую Витгенштейн-читалку
(вместе с Nachlass, на XML-базе по образцу HWPh) отложено; набор данных `tlp-data.json` делается так,
чтобы позже стать одним из источников такой базы.

Ниже — разбор проекта HWPh (`hwph-xml`) как образца: что там сделано, что уместно перенести сюда,
чего не нужно, и что «Трактату» нужно сверх HWPh.

## 1. Как устроен HWPh (образец)

Четыре слоя.

1. **Подготовка источников.**
   - `pdf_tools/hwph2md.py` — PDF → Markdown со своими соглашениями: заголовок статьи (front matter),
     сноски `[^n]`, метки колонок книги `⟦N⟧`, формулы `$…$` / `$$…$$`, картинки `![](img/…)`.
   - `pdf_tools/glyph_map.json` — 264 картинки PDF, каждая по отпечатку md5 получает решение одного
     из пяти видов: `sym` (знак Юникода), `tex` (строчная формула), `texd` (выключная), `table`
     (таблица Markdown), `img` (остаётся картинкой). Решения проверены глазами на «контактных листах»:
     слева картинка, справа результат, отрисованный так же, как в читалке (KaTeX, STIX).
   - `pdf_tools/hwph_ocr.py` — абзацы, набранные картинкой: прозу читает Tesseract, а участки
     с формулами размечены вручную прямоугольниками (в пикселях) с готовой записью TeX/Unicode;
     слова, попавшие в участок, заменяются его формулой.
   - `epub2md/` (`align.py`, `transfer.py`) — две выгрузки одного текста (epub и PDF) выравниваются
     по словам (difflib по свёрнутым словам), из каждой берётся лучшее: текст из epub, колонки,
     формулы, рисунки — из PDF.
   - `lib/img_svg/` — схемы, обведённые в SVG: подписи схем попадают в поиск, в тёмной теме схемы
     берут цвет текста.
2. **База.** `md2xml.py` собирает одну XML-базу (`<articles>`, `<xrefs>`, `<register>`, `<persons>`,
   таблицы свёртки знаков `<fold>` и т. д.); тело статьи — проверенный XHTML.
3. **Порождение читалки.** XQuery (Saxon, `xq/*.xq`) пишет ~15 тыс. файлов; `split.py` раскладывает
   поток; `manifest.json` перечисляет файлы для кравлера `crawl.py`; Java-сервер `HwphServer` отдаёт
   страницы прямо из базы и подхватывает правки; `compare.py` сверяет сборки побайтно, как JSON и как DOM;
   `finish.py` сверяет манифест с папкой.
4. **Оболочка** `static/hwph_ui.html` — одностраничное приложение, открываемое с диска:
   - данные — скрипты вида `HWPH.put(key, value)` (страница с `file://` грузит скрипты, но не fetch);
   - каркас: шапка, список слева, текст, правая колонка («rail»); тема светлая/тёмная, размер
     шрифта, выбор шрифта, «только текст», печать; настройки — в localStorage;
   - поиск: свёртка (регистр, умлауты, ударения, ß = ss, придыхания), фразы, маски `*` `?`, OR, NOT,
     NEAR, скобки, терпимость к написанию, список словоформ, подсказки при вводе, переход по совпадениям
     (`n`/`N`), подсветка найденного, «список мест», тематический поиск, цветные фильтры;
   - чтение: сноски всплывают при наведении, формулы — KaTeX без сети (`static/katex`), метки колонок
     печатного издания, «копировать со ссылкой» («HWPh, Bd. 12, Sp. 518, Art. ‹…›»);
   - своя работа: пометки (четыре цвета, с контекстом ±40 знаков, переживают пересборку), заметки,
     выборки; выгрузка/загрузка всего в JSON;
   - графы ссылок и лиц (SVG, карточка узла, добавление/снятие узлов);
   - интерфейс на 4 языках: `static/i18n.js` (ключ называет место, формы числа через
     `Intl.PluralRules`, атрибуты `data-i18n*`), сторож `tools/i18n_check.py`;
   - отдельная статическая страница на каждую статью (`pages/<id>.html`, `page.css`), читаемая без JS.

## 2. Что перенести

### В подготовку текста (это и есть оставшаяся работа по данным)

| Образец в HWPh | Применение здесь |
|---|---|
| `glyph_map.json` (решения о картинках) | Таблица решений о формулах вынести из `build_all.py` в `work/fixes.json`. Ключ — (редакция, номер положения), виды те же: `tex`, `texd`, `table`, `svg` (схема), `text` (замена фрагмента) |
| Контактные листы | **Листы вычитки 1961 г.**: для каждого формульного/подозрительного положения — кусок скана (из `ocr/pg-NNN.pgm` по координатам из TSV) рядом с нашим текстом, отрисованным KaTeX. Одна HTML-страница; позволяет вычитать 150–300 мест подряд |
| `hwph_ocr.py` (участки формул) | Для формульных положений 1961 (5.5x–6.2x, 4.1272–4.1273, 4.24, 5.242, 5.2522, 5.501–5.532, 6.1201…): прозу оставляет Tesseract, формулу подставляет размеченный участок |
| `epub2md/transfer.py` (выравнивание двух выгрузок) | Второй «свидетель» — OCR-слой Internet Archive в самом PDF 1961. Выровнять его с Tesseract по словам: расхождения = подозрительные слова. Точнее, чем словарная проверка `qa61.py` (189/129 положений с массой ложных срабатываний) |
| `img_svg/` | Схемы в SVG: в PDF 2005 схемы 6.1203 и глаз 5.6331 **векторные** (16 и 6 контуров на стр. 189 и 183) — вынуть напрямую (PyMuPDF `get_drawings`); в 2023 они растровые (стр. 128–129, 123). Рисунок по сути один на все редакции — один SVG с подписями-параметрами И/Л, W/F, T/F |
| `md_table` в `md2xml.py` | Таблицы 4.31, 4.442, 5.101 — из моноширинных блоков в настоящие таблицы |

### В читалку

- Каркас и вид: шапка, левая панель (дерево/оглавление), текст, правая колонка; тема, размер и
  выбор шрифта, «только текст», печать — палитра и переменные CSS `hwph_ui.html` подходят как есть.
- Данные внутри файла (или скриптом рядом) — открывается с диска.
- KaTeX без сети (взять `static/katex` из HWPh) и подстановка `$…$` / `$$…$$`.
- Сноски и примечания переводчиков — всплывают при наведении, щелчок ведёт к тексту примечания.
- Поиск: та же свёртка (плюс ё = е), фразы, маски, OR/NOT/NEAR, подсветка, переход по совпадениям,
  подсказки при вводе (номера положений, термины). Указатель на диске не нужен: весь корпус
  (~2 тыс. текстов) ищется в памяти; выбор «где искать»: редакции, комментарии, примечания.
- Пометки, заметки, выборки положений в localStorage с выгрузкой/загрузкой JSON.
- Копирование со ссылкой: «ЛФТ 4.0312 — пер. К. Королева, 2023, с. 81» (страницы каждого положения
  в каждой редакции уже известны парсерам: `ru2023.json → entries[].page`, `lp1961.json → pages`;
  для 2005 — добавить).
- Интерфейс на русском, немецком, английском (языки самих текстов): `i18n.js`-подход и сторож перевода.
- Цветные фильтры (до 4 выражений своим цветом) — для слежения за терминами по дереву.

## 3. Чего не брать

- XQuery, Saxon, Java-сервер, `split.py`, `manifest.json`, `crawl.py`, `finish.py` — машинерия для
  15 тыс. файлов из базы в 181 МБ; здесь весь корпус — несколько мегабайт.
- Шардированный словарный и позиционный указатели — поиск идёт прямо по текстам в памяти.
- `hwph_cite.py`, `persons_fix.json`, регистры тома 13, карта колонок `colmap`, смещение страниц epub —
  у «Трактата» нет такого материала; имён (Фреге, Рассел, Уайтхед, Кант, Дарвин, Герц…) десяток,
  они описываются вручную.
- `compare.py` — нужен только при двух сборках одной читалки; при единственной не нужен.

## 4. Что «Трактату» нужно сверх HWPh

- **Параллельный текст по номеру.** Номер — общий ключ всех редакций. Выбор 1–4 колонок
  (нем. 1961 | Огден | Королев | Руднев с комментарием), синхронная прокрутка по положениям.
- **Виды одного текста:**
  - сплошной по порядку номеров (как у автора);
  - «фрактальное дерево» (как в издании 2023) — `tlp_tree.layout()` уже есть;
  - сворачиваемое оглавление-дерево с группами детей (у 3: {3.001}, {3.01–3.05}, {3.1–3.5});
  - цепочка предков у каждого положения (1 → 1.1 → 1.13), соседи по ветви.
- **Комментарии Руднева отдельным слоем:** включаются/выключаются; совместный комментарий «к a–b»
  подсвечивает все свои положения.
- **Сводка терминов между переводами.** Sachverhalt — atomic fact (Огден) — «позиция» (Королев) —
  «положение вещей» (Руднев); Sachlage, Tatsache, Gegenstand, Satz, Bild, Form der Abbildung и т. д.
  Таблица «термин → как передан в каждой редакции → в каких положениях»; строится почти
  автоматически по сопоставлению номеров (полуавтомат: словарь соответствий + подсчёт по положениям).
- **Ссылки между положениями:** упоминания номеров в тексте и в комментариях Руднева → граф связей
  поверх дерева; **карта «Трактата»** — дерево, размер узла = число потомков, щелчок ведёт к положению.
- **Предисловия, посвящения, эпиграфы, примечания** каждой редакции — отдельные страницы.

## 5. Данные читалки: `tlp-data.json`

```
{
  "editions": {
    "de1961": {"lang": "de", "title": …, "source": …, "missing": []},
    "en1961": {…}, "ru2005": {…, "missing": ["2.182", …]}, "ru2023": {…}
  },
  "props": {
    "2.0121": {
      "parent": "2.012", "group": 0, "children": [[…], …],
      "text":  {"de1961": md, "en1961": md, "ru2005": md, "ru2023": md},
      "page":  {"de1961": 34, "en1961": 35, "ru2005": 27, "ru2023": 44},
      "comments": {"ru2005": [{"covers": ["2.0121"], "text": md}]},
      "refs": ["2.013", …]
    }, …
  },
  "front":   {"<edition>": {dedication, motto, preface[], comment[]}},
  "notes":   {"<edition>": {"<label>": md}},
  "figures": {"6.1203-1": "<svg …>", …},
  "terms":   [{"de": "Sachverhalt", "en": [...], "ru2005": [...], "ru2023": [...], "props": [...]}]
}
```

Сборка: `work/build_data.py` (из `norm_*.json` + `fixes.json` + SVG) с проверкой полноты
(526 номеров, у каждой редакции — отсутствующие только из её списка `missing`, все `[^…]`
разрешены, все `$…$` проходят разбор KaTeX). Читалка: `reader/tlp_reader.html` (шаблон) +
`work/build_reader.py`, вклеивающий данные и KaTeX → `out/tlp_reader.html`.
